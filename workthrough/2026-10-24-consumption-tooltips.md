# 한도 소비 툴팁과 구독 가치 계산 범위

## 요청과 확인

- 한도 소비 차트의 툴팁을 토큰 분석과 비슷하게 맞추고, 모델을 아는 소비가 리포트의 구독 가치에 포함되는지 확인했다.
- 작업 시작 시 main은 `fe09a73`, 운영 릴리스는 v0.9.0이었다. 별도 `fix/consumption-chart-tooltips` worktree와 uv 0.12.23의 잠긴 환경에서 작업했다.
- 한도 소비의 원본 단위는 `%`다. 모델 이름만으로 입력·출력·캐시 토큰을 알 수 없으며, 현재 구독 가치의 `period_cost`는 모델·날짜별 원본 요청 토큰에 적용할 단가가 있을 때 계산된다. 새 소비 테이블은 이 계산에 더하지 않는다. 같은 작업의 원본 요청 토큰이 별도로 수집됐다면 기존 기록으로 반영된다.

## 변경

- 기본 SVG title 대신 공통 툴팁 스타일로 날짜, 제공사 기준일, 기능/모델 색상과 소비율, 그 날짜의 표시 항목 합계와 선택선을 보여 준다.
- 마우스·터치·방향키·Home·End, 클릭/Enter의 상세 선택, Escape 닫기를 지원한다. 긴 목록은 차트 아래에서 스크롤하고 모바일 가로 범위 안에 표시한다.
- 미수신·분류값 미제공을 실제 0%와 구분하며 작은 양수와 합계 불일치·근사·불완전한 제공 범위를 보존한다. 높이가 바뀐 툴팁이 ResizeObserver를 통해 스스로 지워지지 않도록 너비 변화만 차트 재배치에 사용한다.
- 리포트 화면과 사용법·README에 구독 가치의 환산 범위를 설명한다. 수집·집계·가격 계산·DB·외부 의존성은 변경하지 않는다.
- 버전을 0.9.1로 올리고 pyproject.toml·uv.lock 및 설치·운영 안내를 함께 갱신한다.

## 검증과 배포

- 독립 환경의 Python 549개, 전체 웹 JavaScript 문법, Node 42개 검사를 통과했다.
- 로컬 합성 브라우저 네 스위트(`smoke`, `dashboard`, `model_visibility`, `codex_activity`)를 통과했다. 새 툴팁은 Chromium 1440px·390px·320px에서 마우스·터치·키보드, 12개 모델의 스크롤, 분류·기간 변경, 실제 0·작은 양수·미제공·미수신과 합계 불일치를 확인했다. 기존 토큰 분석의 툴팁·색상·터치·키보드 회귀도 통과했다.
- 스크린샷을 확인하고 모바일 기본 탭 강조색이 툴팁 위에 덮이던 표시를 제거했다. 키보드 포커스 표시는 유지했다. 합성 API 검사이며 실제 운영 화면 확인과 구분한다.
- 실제 Tailscale 인증으로 운영 API를 읽고 새 화면 자산만 적용한 미리보기에서도 1440px·390px·320px의 기능별·모델별 툴팁 합계가 일별 원본 값과 일치했다. 이 단계는 운영 서비스 전환이 아니다.
- 첫 CI에서 모바일 너비 변경 직후 SVG가 교체돼 검증의 스크롤 대상이 사라지는 경계를 발견했다. 명시적 차트 렌더링에도 현재 너비를 기록해 중복 재배치를 줄였고, 브라우저 검사는 새 너비가 적용된 뒤 유지되는 차트 컨테이너를 스크롤하도록 보완했다.
- 외부 패키지는 바꾸지 않았고 pyproject.toml·uv.lock의 앱 버전만 0.9.1로 함께 갱신했다. 계산 경로를 조사했지만 집계는 수정하지 않아 운영 원본 전체 재대조는 반복하지 않았다.
- 임시 화면과 개인 운영 데이터는 커밋하지 않는다.

## 릴리스와 실제 운영 검증

- [PR #84](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/84)의 [최종 CI](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/40067414560)에서 전체 브라우저 22개 스위트와 모든 필수 검사를 통과하고 merge commit `2cb2f0b`로 main에 병합했다. [main CI](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/40067620517)도 통과했다.
- 같은 커밋에 `v0.9.1` 태그를 push하고 [릴리스 CI](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/40067627838)를 거쳐 [불변 릴리스](https://github.com/jihoon22-lee/llm-usage-dashboard/releases/tag/v0.9.1)를 게시했다. 내려받은 자산 4개의 SHA-256과 manifest의 저장소·커밋·태그·실행 ID, wheel·sdist 각각의 웹 자산 19개를 대조했다. 릴리스 설명 갱신 후에도 자산 ID·크기·해시와 불변 상태는 같았다.
- 운영 Python 3.14.4의 실제 런타임 패키지 8개가 대상 lock과 일치해 기존 코드 전환 배포기를 사용했다. 배포기가 Python 549개·Node 42개·문법 검사를 다시 통과한 뒤 2026-10-24 실행 코드를 v0.9.1 `2cb2f0b`로 전환했다. 운영 `.venv`는 동기화하지 않았다.
- 웹·수집기의 실제 실행 디렉터리와 `active/running`, `NRestarts=0`, health 및 새 heartbeat를 확인했다. 설정·개인 설정·단가 파일 해시와 DB 테이블 정의는 전환 전과 같았다. 직전 v0.9.0 릴리스와 기존 복구용 백업은 보존한다.
- 자산을 바꾸어 끼우지 않은 실제 Tailscale 인증 화면에서 Chromium 1440px·390px·320px의 기능별·모델별 툴팁을 확인했다. 각 툴팁 합계는 API의 일별 원본 값과 표시 반올림 범위 안에서 일치했고, 모바일 터치·긴 목록 스크롤·가로 범위·키보드·리포트 설명·기존 토큰 차트도 확인했다. 실제 화면의 `지금 갱신` 요청이 HTTP 202로 접수되고 요청 ID에 해당하는 수집 완료 후 툴팁이 다시 표시됐다. 브라우저·CSP 오류는 없었고 운영에서 제공한 변경 JS·CSS의 해시도 릴리스 파일과 일치했다.

구독 가치 계산에 새 소비율을 추가하지 않았으며, 원본 토큰·단가가 없는 사용의 환산 가치가 미산정이라는 제약은 유지한다.
