# 수집 정확성 수정 (전체 코드리뷰 후속 1차)

## 범위

- 기준은 main `35ec194`(0.14.0 배포 기록까지)다. 전체 코드리뷰에서 나온 항목 가운데 저장되는 데이터가 틀리거나 수집이 멈추는 다섯 건만 다뤘다.
- 나머지 리뷰 항목(하트비트 기록 주기, 알림·리포트 try 분리, 알림 전송 리다이렉트, 오류 원문 노출, 유휴 구독 판정, 모델명 접미사 effort 판정 등)은 이 작업에 넣지 않았다.

## 고친 것

- **Antigravity 요청의 추론 수준이 지워졌다.** 요청을 다시 저장할 때 `INSERT OR REPLACE`의 열 목록에 `effort`가 없어, 0.14.0 마이그레이션이 모델 이름에서 채운 값이 NULL로 바뀌었다. 저장할 때 모델 이름이 밝힌 수준을 함께 쓴다. 이미 지워진 행은 수집기가 한 번(`antigravity-effort-v1`) 모델 이름으로 되살린다. 대화 DB가 없어졌거나 바뀌지 않아 다시 읽히지 않는 요청도 포함된다.
- **Claude 클라우드 세션의 추론 수준을 읽지 않았다.** 대화 본문을 버리는 허용 목록에 `effort`가 없었다. 목록에 더하고 클라우드 `PARSER_VERSION`을 5로 올려, 이미 읽은 세션도 한 번 다시 읽는다.
- **클라우드 세션의 해석 실패 기록이 사라졌다.** 세션마다 transcript와 추가 누계를 차례로 읽는데, 두 번째 읽기가 첫 번째의 실패 기록을 지웠다. 기록은 세션을 처음부터 다시 읽을 때만 지우고, 항목 자신의 ID로 남겨 두 읽기에서 만난 같은 항목을 한 번만 센다. `claude-cloud` 수집 상태에 `해석 실패 N건`을 적고 `partial`로 표시한다.
- **클라우드 조회의 `Retry-After`에 상한이 없었다.** 계정 한도 조회와 같은 `retry_delay`와 하루 상한(`MAX_RETRY_AFTER`)을 쓴다.
- **깊게 중첩된 기록 한 줄이 수집원 전체를 멈췄다.** JSON 해석기의 `RecursionError`가 줄 단위 오류 목록에 없어, 그 파일과 같은 경로의 뒤따르는 파일이 매 수집마다 읽히지 않았다. 해석 실패 한 줄로 세고 계속 읽는다. 텔레메트리 수신기도 같은 본문에 400으로 응답한다(이전에는 응답 없이 연결이 끊겼다).

## 검증

- 회귀 검사 6개(신규 4, 확장 2)는 수정 전 코드에서 모두 실패하고 수정 후 통과한다: `tests/test_antigravity_history.py`, `tests/test_cloud_usage.py`, `tests/test_collection_integrity.py`, `tests/test_reconciliation.py`.
- `.venv/bin/python -m unittest discover -s tests -q`: 630개 통과.
- 여기까지는 fixture 검증이다. 운영에는 배포하지 않았고, 실제 데이터에서의 효과(지워진 Antigravity 행 복구, 클라우드 세션의 추론 수준 수신)는 배포 후 첫 수집 주기에 확인해야 한다.

## 남은 제약

- 클라우드 응답이 로컬 transcript처럼 항목 최상위에 `effort`를 준다는 것은 fixture로만 확인했다. 실제 응답에 없으면 값은 계속 `미기록`이고, 세션을 한 번 다시 읽는 비용만 든다.
- 배포하면 클라우드 세션 전체를 한 번 다시 읽는다. 세션이 많으면 여러 수집 주기에 걸쳐 `과거 이벤트 이어 읽기`로 표시된다.
- 읽을 수 없는 항목이 있는 클라우드 세션이 목록에 남아 있는 동안 `claude-cloud`는 `partial`이다.
