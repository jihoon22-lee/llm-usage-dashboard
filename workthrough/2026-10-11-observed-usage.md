# 관측 데이터 중심 화면 개선 · 0.4.0

## 요청과 범위

사용자는 대부분 판단 보류만 표시하는 계획 탭과 보유 자원이 아닌 Claude 지출 한도
카드를 검토한 뒤, 권장 개선 전체의 구현·문서·버전 갱신·태그·릴리스·운영 배포를 요청했다.
시작 main은 `745a99b`, 공개 버전은 0.3.0이다. 독립 작업 브랜치와 worktree에서
uv 0.12.23 `uv sync --locked`로 개발 환경을 준비했다. 운영 환경은 아직 변경하지 않았다.

## 검토 결과와 구현

- 계획 탭·한도 탭 계획 요약·작업시간 입력·오늘/주간 전망을 제거한다. 네 탭과 단축키
  1~4를 사용하고 기존 `view=plan` 주소·저장된 선택은 한도로 연결한다.
- `/api/limits`에서 작업 판단 응답을 제거한다. 과거 계획 쿼리는 한도 조회를 막지 않는다.
  관측 시계·오프라인 경과·자원 갱신은 별도 웹 모듈에서 유지한다.
- 한도 카드의 지속 시간·소진 예측·균등 소비 기준선과 예측 알림을 제거한다. 최근 30분
  안에서 연속 15분 이상 확인된 실제 감소량만 표시한다. 관측된 0은 유효한 값이며,
  부족한 이력·오래된 값·계정 미확인은 보조 줄을 만들지 않는다. 과거 그래프는 원본
  관측과 공백을 보존하고 미래 예측선을 그리지 않는다.
- 자원 패널은 보유 초기화권·크레딧으로 한정한다. 지출 제한은 독립 카드·수동 연결
  선택지에서 제외하고 필요한 크레딧의 사용 조건으로만 남긴다. 비활성화 여부는 통화
  미확인과 구분하되 서로 다른 단위의 금액은 연결하지 않는다.
- 확인된 만료일 순으로 보유 자원을 정렬한다. 사용·만료된 초기화권 상세는 접고,
  잔액 0·이전 계정·중복 참고 기록은 기존 접이식 목록에 남긴다. 받은 적 없는 수치로
  빈 카드를 만들지 않으며 조회 실패한 기존 잔액은 이전 확인값으로 보존한다.
- 사용량 탭에 최근 1시간 빠른 보기를 추가한다. 원본 이벤트의 정확한 60분 구간을
  집계하고 요약·차트·모델·프로젝트·세션·CSV에 동일 범위를 적용한다. 시간별 롤업의
  경계 버킷을 통째로 포함하지 않는다. 상세 조회는 요약의 종료 시각을 사용하며,
  수집이 멈춰도 시간 경과에 따라 구간에서 빠진 기록을 캐시가 유지하지 않게 한다.

## 검증 기록

- 변경 전 운영 DB의 읽기 전용 사본에서 최근 7일·30일의 필드 충족 여부, 계정별
  연속 한도 이력과 자원 관측을 검토했다. 서비스·모델·프로젝트·세션별 분류 합계가
  원래 기록과 일치했다. 개인 이름·경로·잔액·계정 식별자·원본 응답은 기록하지 않는다.
- 새 Python 검사는 KST 자정 교차, 구간 시작 포함/종료 제외, 미래/직전 이벤트 제외,
  토큰 중복 합산 방지, 미귀속 기록, 범위 필터·비용·이전 구간 비교, 캐시 경과,
  요약/상세 기준 시각과 잘못된 API 인자를 확인한다.
- 현재 Python 335개와 JavaScript 29개 단위 검사, 전체 웹 JavaScript 구문 검사 통과.
- 브라우저 17개 묶음에서 네 탭·이전 주소·키보드·모바일·수동 기록 충돌/재시도·
  오프라인 경과/복구·삭제된 예측 알림을 검증했다. 최근 1시간은 320/390/1440px에서
  원본 경계 합계·상세 조회·미귀속·CSV·저장 URL·시간 경과를 확인했다. 일별로 바꿔
  확대해도 잘못된 날짜 범위를 만들지 않으며 툴팁에 실제 부분 구간을 표시한다.
- 수치 미수신은 빈 카드가 되지 않고, 기존 잔액 조회 실패는 이전 확인값으로 남는
  화면을 검증했다. 초기화권의 만료 시각이 지나면 재확인 상태로 바꾸되 원본 개수를
  자동 차감하지 않는다. 이미 원본에서 만료 처리된 과거 상세는 현재 수신을 막지 않는다.
- 운영 DB의 일관된 읽기 전용 사본에서 기존 이벤트 수·토큰 합계 보존을 확인했다.
  새 60분 집계를 서비스·모델·프로젝트별로 원본 SQL과 대조하고 요약/상세 합계가
  일치함을 확인했다. `tests/verify_record_totals.py --database <비공개 사본>`에서
  Codex 정상·카운터 초기화·불완전 시작 이력 대조, Antigravity·Devin 원본 대조를
  통과했다. 동일 시각의 모호한 이력은 별도 분류이며 완전 복구를 뜻하지 않는다.
- 0.4.0 wheel/sdist의 파일 목록·메타데이터·18개 웹 자산 해시·소스 밖 wheel 설치를
  확인했다. uv 0.12.23으로 임시 태그 clone·새 환경·문서의 초기 설치 절차를 검증했다.
  프로젝트 버전만 바뀌고 외부 의존성은 같다. 공개 파일 개인정보 패턴·로컬 문서 링크·
  diff 검사를 통과했다. 두 문서 이미지는 최신 합성 화면으로 교체했다.
- 여기까지 운영 서비스·운영 가상환경은 변경하지 않았고 실제 배포 후 화면 검증은
  아래 공개 릴리스와 운영 적용 단계에서 별도로 기록한다.

## 남는 제약

- 토큰은 수집된 로컬 기록의 집계다. 현재 실행 중인지, 계정 한도 감소의 원인이
  어느 세션인지, 기록되지 않은 원격 사용이 없는지는 판정하지 않는다.
- Antigravity는 프로젝트 원본이 없고 과거 일부 Codex 이력도 귀속이 불완전하다.
  미분류·미귀속을 합계에서 버리거나 임의 프로젝트로 채우지 않는다.
- 현재 계정의 추가 자원 반복 수신은 확인했지만 장기 가용성을 보장하지 않는다.
  만료일 미수신을 무기한 자원으로 해석하지 않고 초기화 시각만으로 잔액을 복원하지 않는다.
- 실제 제공사의 초기화권 사용·크레딧 구매·유료 사용은 검증 범위에 없다.

  자원 브라우저 검사가 이전 계획 주소 이동 직후 비동기 데이터 도착 전에 fixture를

  우회하지 않고 보완 커밋의 결과를 확인한 뒤 병합한다.
- 기존 backups 위치에 운영 DB의 일관 사본·설정·이전 lock·운영 환경·패키지 버전의
  비공개 복구 백업을 준비했다. 웹·수집기는 기존 0.3.0으로 실행 중이다.
