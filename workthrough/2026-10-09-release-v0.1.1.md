# v0.1.1 문서 최신화·버전 범프·릴리스

## 범위와 기준

사용자는 문서 최신화, 버전 범프, 버전 태그와 GitHub Release 게시를 요청했다. 기준 main은 `a933dd6`, 기존 공개 태그/릴리스는 `v0.1.0`이다. 이후 수정은 정확성·안정성·사용성 보완이므로 패치 버전 `0.1.1`로 올린다.

독립 `release/v0.1.1` 브랜치/worktree와 uv 0.12.23 환경에서 검증한다. 제품 로직·의존성 버전·DB·인증·운영 서비스를 변경하지 않는다. 현재 운영 코드는 앞선 작업에서 배포한 `ec51213`이며 이번 GitHub 릴리스 게시와 운영 재배포는 구분한다.

## 변경과 실행 순서

1. pyproject.toml의 버전과 uv.lock의 프로젝트 버전을 0.1.1로 맞춘다. 다른 패키지의 lock 변경이 없는지 비교한다.
2. CHANGELOG에 v0.1.0 이후 전체 변경, README/설치 안내에 v0.1.1 설치, 운영 문서에 의존성이 같은 업데이트와 v0.1.0→v0.1.1 전환을 구분한다. 기여 안내에 실제 릴리스 절차를 반영한다.
3. 내용·링크·개인정보·버전 일치와 릴리스 가드, wheel/sdist의 메타데이터·자산·독립 설치 및 Git 태그 설치를 검증한다. 기존 전체 Python/JavaScript/브라우저/보안 검사는 PR과 태그 워크플로의 필수 CI로 실행한다.
4. 보호된 PR/ci-required를 거쳐 merge commit으로 main에 병합한다. 일치하는 main 커밋에 v0.1.1 태그를 생성·push하고 기존 Release 워크플로의 동일 산출물 게시를 기다린다.
5. 공개 자산 4개를 내려받아 체크섬·manifest의 버전/태그/커밋/CI 출처를 검증한다. 기존 v0.1.0 태그와 자산은 덮어쓰지 않는다.
6. 실제 PR·CI·태그·릴리스 결과를 이 기록에 갱신해 문서 PR로 통합하고, 병합한 작업 브랜치/worktree·임시 패키지·환경·로그를 정리한다.

## 검증·게시 결과

- pyproject/lock 프로젝트 버전은 0.1.1로 일치한다. uv 0.12.23이 lock 형식 revision을 3에서 5로 갱신했으며, 그 외 모든 의존성 항목은 이전 lock과 완전히 같다.
- 내용·로컬 문서 링크·개인정보 패턴·diff 검사 및 릴리스 관련 회귀 14개가 통과했다.
- 문서의 태그 clone → 로컬 main → uv 고정 설치 → 합성 init/import가 통과했다. wheel/sdist 빌드, 독립 wheel 설치·의존성 검사·CLI·모든 웹 자산·manifest·SHA256SUMS 검사도 통과했다. 로컬 산출물은 검증용이며 게시에는 태그 CI의 동일 산출물을 사용한다. 이후 PR/태그 CI 결과는 아래와 같다.
- 버전 PR [#19](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/19)을 merge commit `813a3edd95622b64d90a96a8e6f59c5082027e34`로 병합했다. 버전 변경 커밋은 `bd58cdb`다.
- [PR CI](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/37940292949), [main CI](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/37940646844)의 모든 필수 검사와 ci-required가 성공했다. 자동 의존성 그래프 갱신과 실제 CI 워크플로를 구분해 확인했다.
- 위 merge SHA에 annotated tag `v0.1.1`을 생성·push했다. 태그 객체는 `0d7129720c6435ae5f187b2117af255a8db665fc`이며 원격의 peeled commit이 merge SHA와 일치한다.
- [Release 워크플로](https://github.com/jihoon22-lee/llm-usage-dashboard/actions/runs/37940975670)의 release-guard, 전체 검사, ci-required, publish가 모두 성공했다. 게시 job은 검증한 artifact를 사용했으며 로컬 빌드로 교체하지 않았다.
- [v0.1.1 GitHub Release](https://github.com/jihoon22-lee/llm-usage-dashboard/releases/tag/v0.1.1)가 정식 최신 릴리스로 게시되었다. draft/prerelease는 false, immutable 보호는 true다. 변경 사항·업데이트 주의사항을 릴리스 노트에 반영하면서 커밋/CI/tested artifact ID 출처를 보존했다.
- 공개된 `llm_usage_dashboard-0.1.1-py3-none-any.whl`, `llm_usage_dashboard-0.1.1.tar.gz`, `release-manifest.json`, `SHA256SUMS` 4개를 다시 다운로드했다. 전체 체크섬, manifest의 버전/태그/커밋/CI run ID/저장소, wheel·sdist의 0.1.1 메타데이터와 웹 자산 16개의 해시를 검증했다.
- 릴리스 노트 편집 전후의 신규 자산 ID·digest·크기가 모두 같고, 기존 v0.1.0 자산 4개의 ID·digest·크기와 immutable 보호도 그대로다. 기존 태그를 이동하거나 자산을 덮어쓰지 않았다.

## 완료 범위와 정리

문서 최신화·버전 범프·PR/main 병합·원격 태그·GitHub Release 게시와 실제 게시 자산 대조를 완료했다. 제품 로직·의존성 버전은 변경하지 않았으며 PyPI 게시나 운영 서비스 재배포·가상환경 동기화는 수행하지 않았다. 기존 운영 `ec51213`과 공개 릴리스의 기능 코드는 같으며 버전 메타데이터·문서만 달라졌다.

최종 결과 기록은 별도 문서 PR로 통합한다. 그 후 병합된 릴리스/기록 브랜치와 worktree, 로컬 빌드·다운로드 사본·임시 환경·로그를 정리한다. 공개 태그와 릴리스 자산은 유지하고 기본 checkout은 깨끗한 main으로 남긴다.
