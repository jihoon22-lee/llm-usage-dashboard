# 추론 수준별 사용량과 장문 구간 단가 확인

## 요청과 확인

- 추론 수준이 달라도 같은 단가로만 환산해 온 것을 구분할 방법이 있는지, 장문 구간 단가가 구독에도 적용되는지 확인한다. 브랜치는 `feat/effort-levels`(main `dc01b3c`)다.
- 원본 기록의 필드 이름만 훑어 확인했다(대화 내용은 읽지 않음): Claude Code 응답 기록의 `effort`와 `message.usage.speed`, Codex 턴 설정의 `effort`. Claude는 10월부터(10월 파일 774개 중 770개), Codex는 8월부터 모든 파일에 있다. Devin·Antigravity는 모델 이름 접미사(`(max)`, `-high`)에 있다.

## 장문 구간 단가: 적용하지 않는다

- [Codex 요금 안내](https://learn.chatgpt.com/docs/pricing)는 "GPT-6.1 Sol usage drawn from your subscription has no long-context surcharge in Codex or ChatGPT Work"라고 밝히고, 구독 크레딧 단가를 모델마다 하나만 둔다(GPT-6 Astra 입력 250·출력 1,250 크레딧/1M으로 API 기본 구간과 같은 비율). "API token prices are separate from subscription usage"라고도 적는다.
- Anthropic의 Haiku 5.5 100K 초과 단가는 API 요금표의 항목이고, 구독 사용량에 장문 가산을 둔다는 문서는 찾지 못했다.
- 운영 기록에서 `gpt-6-astra` 토큰의 28.9%가 272K 초과 요청이지만, 모두 구독 경로라 기본 구간 환산을 유지한다. 단가표 주석과 사용법에 근거를 적었다. API 키 경로를 수집하게 되면 그때 구간을 나눠야 한다.

## 추론 수준 수집

- 토큰 단가는 추론 수준과 무관하다(추론 토큰은 출력으로 과금). 달라지는 것은 요청당 토큰량이므로 단가가 아니라 사용량의 차원으로 넣었다.
- `events`에 `effort`·`speed` 열을 더하고, 시간별 롤업의 키에 `effort`를 넣었다(롤업 버전 4, 시작할 때 다시 만든다).
- Claude Code는 응답 기록의 `effort`·`speed`를 읽는다. Codex는 턴 설정의 `effort`를 `session_effort`에 남기고 각 요청이 자기 시각 이전의 가장 최근 값을 갖는다. 모델 이름에 수준이 있는 경로는 이름에서 읽는다. 값이 없으면 비워 두고 다른 수준으로 채우지 않는다.
- 파서 버전을 4로 올려 남아 있는 원본을 한 번 다시 읽는다. 원본이 지워진 요청은 `미기록`으로 남는다.
- `/api/usage`에 `efforts`(경로·모델·수준별 요청 수, 토큰, 출력, 추론, 비용)를 더하고, 분류에 `effort`를 더했다.
- 사용량 탭에 **추론 수준별 사용** 패널(요청당 토큰·출력·비용, 출력 중 추론 비중)을, 분류에 **추론 수준별**을 더했다.
- `speed`는 수집만 한다. 지금까지 기록은 모두 `standard`다. fast 모드는 토큰 단가가 실제로 다르므로 사용이 생기면 단가에 반영해야 한다.

## Codex 카운터 초기화 누락: 고치지 않는다

보류 항목이던 "초기화 직후 첫 요청이 이전 구간보다 크면 초기화를 감지하지 못함"을 운영 DB에서 확인했다. 해당 형태는 원본 응답 기록이 없는 세션에만 생기는데, 그런 세션 967개는 모두 9월 이전 것이고 새 기록에는 생기지 않는다. 전체 이력에서 조건에 맞는 지점은 1곳, 최대 약 12만 토큰(전체 Codex 627억 토큰의 0.0002%)이다. DB 열 추가와 과거 재해석의 위험이 얻는 것보다 커서 닫는다.

## 검증

- `tests/test_effort.py` 5개: 모델 이름의 수준, Claude 기록의 수준·속도와 재수집 시 유지, Codex 턴별 수준과 파서 버전 변경 후 소급, 수준별 요약·분류와 합계 일치, 이전 구조 DB의 전환.
- 단위 테스트 623개, 웹 JS 문법 검사, 합성 데이터 브라우저 스위트 24개 통과.
- 운영 DB를 SQLite 백업 API로 임시 폴더에 복사해 전환과 재수집을 미리 돌렸다: 전환 1.9초, 재수집 186초, 전환 전후 토큰·요청 합계 동일(그 사이 새로 생긴 12건 제외), 롤업 자체 검사 통과. 수준이 채워진 비율은 Codex 요청의 99%, Claude Code의 82%였다. 복사본은 삭제했다.
- 복사본으로 본 최근 30일: `claude-opus-5-5`의 요청당 출력이 medium 593 → high 770 → max 1,190 토큰, 출력 중 추론이 41% → 33% → 63%.
- 운영 서비스에는 적용하지 않았다. DB 구조가 바뀌므로 배포 전에 백업이 필요하다.
