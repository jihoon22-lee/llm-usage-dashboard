# 5단계 코드리뷰 후속 수정과 0.7.1 릴리스

## 범위와 절차

- 기준: main `405abb2`, v0.7.0. 리뷰에서 재현한 다섯 문제를 수정한다.
- 수동 자원 계정 선택, 기본 계정 없는 Claude 귀속, 숨긴 단가의 상속, 계정 전환 후 리포트 소진 횟수, 클라우드 보충 후 상위 세션 집계 순서로 작업한다.
- 독립 worktree에서 uv 0.12.23의 `uv sync --locked`로 준비했다. 운영 환경 동기화와 서비스 배포는 이 작업의 범위가 아니다.
- 문제별 회귀 검증과 커밋 후 PR의 필수 CI를 통과해 merge commit으로 main에 병합한다. 버전 PR과 main CI 성공 후 v0.7.1 태그로 기존 Release 워크플로를 실행하고 게시 산출물을 다시 검증한다.

## 구현과 검증

### 수동 자원 계정 선택

- 30초 관측 시계가 선택지를 다시 만들어 추가 Claude 계정이 Codex로 바뀌는 실패를 브라우저 회귀 검사로 확인했다.
- 선택지를 갱신한 뒤 입력 중인 계정을 복원한다. 목록에서 사라진 선택은 확인 필요로 남기고 저장 전에 계정을 다시 선택하도록 한다.
- 신규·기존 자원, 30초 경과·목록 갱신·탭 복귀, 1440/390/320px에서 실제 Flask API 저장 결과가 선택한 계정과 일치했다. `tests/browser_claude_accounts.py`와 `node --check llm_usage/web/resources.js` 통과. 목록에서 사라진 계정의 저장 차단과 재선택도 확인했다.

### 기본 계정 없는 Claude 귀속

- 단독 transcript 소유 계정 키가 있으면 기본 계정의 유무와 관계없이 계정 등록과 같은 경로를 사용한다. 식별된 계정이 별도 홈 하나뿐이어도 구독료 설정과 계정별 사용량에 반영한다.
- 이전 기본 경로 배정은 보정 시작 전 기본 계정이 미확정이며 원본 폴더가 하나로 입증되는 세션만 다시 판정한다. 클라우드 귀속과 이미 확정된 다른 계정은 보존한다. 기존에 기본 계정이 확정됐거나 독립 폴더 여러 개에 복사본이 있으면 과거 계정을 추정해 이동하지 않는다.
- 보정은 한 번 실행하고 트랜잭션 실패 시 다시 시도한다. 중간에 기본 계정을 새로 연결했어도 보정 전 조건을 보존한다. 단독 계정의 구독 가치, 재시작·재실행, 실패 후 재시도, 토큰·요청 수와 롤업 보존을 회귀 검사한다.
- 기존 코드에서 새 귀속·과거 보정 두 검사가 실패하는 것을 확인했고, 수정 후 `test_claude_accounts.py` 33개 검사가 통과했다.
