### 기본 계정 없는 Claude 귀속

- 단독 transcript 소유 계정 키가 있으면 기본 계정의 유무와 관계없이 계정 등록과 같은 경로를 사용한다. 식별된 계정이 별도 홈 하나뿐이어도 구독료 설정과 계정별 사용량에 반영한다.
- 이전 기본 경로 배정은 보정 시작 전 기본 계정이 미확정이며 원본 폴더가 하나로 입증되는 세션만 다시 판정한다. 클라우드 귀속과 이미 확정된 다른 계정은 보존한다. 기존에 기본 계정이 확정됐거나 독립 폴더 여러 개에 복사본이 있으면 과거 계정을 추정해 이동하지 않는다.
- 보정은 한 번 실행하고 트랜잭션 실패 시 다시 시도한다. 중간에 기본 계정을 새로 연결했어도 보정 전 조건을 보존한다. 단독 계정의 구독 가치, 재시작·재실행, 실패 후 재시도, 토큰·요청 수와 롤업 보존을 회귀 검사한다.
- 기존 코드에서 새 귀속·과거 보정 두 검사가 실패하는 것을 확인했고, 수정 후 `test_claude_accounts.py` 33개 검사가 통과했다.
- 연결 점검에서 별도 홈 하나만 식별된 경우도 계정 이름·구독료·수동 자원 선택에 나타나도록 맞췄다. 원래 홈만 쓰는 단일 계정 화면은 기존 표시를 따른다.
- PR #72 자동 리뷰의 추가 지적을 재현했다. 별도 홈으로 먼저 식별한 계정을 나중에 기본 홈에도 로그인하면 경로가 바뀌던 두 검사가 실패했다. 최초 해시 경로를 보존하고 한도 조회 전 귀속에도 키를 예약하도록 보완했다. 상태줄도 같은 계정 경로를 사용한다. 기존 등록·귀속 선행·재시작·다른 계정의 기본 홈 로그인, 구독료·수동 자원·한도·롤업 보존을 포함한 계정 검사 36개와 전체 482개가 통과했다.

### 숨긴 단가의 상속 차단

- 내부 단가표에 명시적 숨김을 남겨 정확한 모델·추론 변형·날짜별 모델의 상위 단가 상속을 차단한다. 공개 설정 응답의 단가 목록은 기존처럼 실제 단가만 반환한다.
- 숨김 상태가 캐시·리포트 revision에도 포함되므로 수집 없이 설정만 바꿔도 비용을 다시 계산한다. 숨긴 상위 모델을 상속하던 모델은 단가 미등록 경고에서도 제외한다. 숨김 해제는 상속을 복원한다.
- 숨김 해제는 별도의 멱등 요청(`unhide`)으로 하위·상위 단가를 복원한다. 사용자 단가 삭제와 구별하며 읽기·쓰기 단가 파일이 같은 경로면 자신을 하위 설정으로 보지 않는다.
- 기존 코드에서 상속 변형 3종과 비용 캐시 검사가 실패하는 것을 확인했다. 수정 후 단가 해석 4개, insights 24개, 설정 브라우저 검사가 통과했다. 기간·누계·세션·프로젝트 비용과 주간·월간 저장 리포트를 확인했다. 사용량/API 검사에는 동일 단가 파일 경계와 반복 숨김 해제도 포함했다.

## 후속 요청에 따른 운영 배포

- 2026-10-23 20:27 KST에 main `e9ed42d`를 기존 배포기로 적용했다. 릴리스 태그 `v0.7.1`과의 차이는 작업 기록 문서뿐이며 실행 코드는 같다. 웹·수집기 프로세스의 실제 실행 디렉터리가 모두 새 릴리스이고 버전은 0.7.1임을 확인했다.
- 운영 `.venv`의 실제 런타임 의존성은 대상 lock과 일치했다. 서비스 정지에는 대화형 sudo 인증이 필요하고 무비밀번호 권한은 기존 재시작 명령에 한정돼 있어, 운영 안내의 코드 전환 경로를 사용했다. 운영 환경은 동기화하지 않았으며 설치 메타데이터의 프로젝트 버전 표기는 기존 0.6.2로 남는다. 실행 코드 버전과 이 표기를 구분한다.
- 전환 전에 SQLite backup API로 복구용 DB 사본을 만들고 `quick_check`·gzip 검증을 통과했다. 편집 가능한 설정 사본과 함께 운영 데이터 폴더에 보존했으며 임시 산출물 정리 대상에 넣지 않는다. 이전 실행 릴리스도 복구용으로 유지한다.
- 배포기의 Python 482개·JavaScript 39개·전체 JavaScript 문법 검사가 통과했다. 두 서비스의 재시작, health 200, 새 collector heartbeat, active/running·Result=success·자동 재시작 0회를 확인했다.
- 배포 전후 실제 사설 HTTPS 인증 화면에서 읽기 전용 브라우저 검사를 통과했다. 데스크톱·모바일 표시와 배포된 resources/format/settings JavaScript 세 파일의 해시가 검증한 소스와 일치했다.
- 실제 화면에서 수동 갱신 POST 한 번을 실행해 요청 ID의 완료와 새 heartbeat를 확인했다. 운영 수동 자원·설정 저장은 실행하지 않았다. 추가 Claude 계정 선택은 1440/390/320px에서 30초 갱신·목록 갱신·탭 복귀 뒤에도 유지됐다. 실제 세션 응답은 100개 이하이며 보충 후 토큰 내림차순이었다.
- 배포 전 백업과 비교해 기존 이벤트 ID 누락은 0건이었다. 저장 주간 리포트 12개가 다시 계산됐고 월간 형식은 1에서 2로 갱신됐다. 기본 계정이 이미 확정된 운영 DB에서는 과거 폴더 귀속 보정이 0건이었으며 불필요한 계정 이동을 하지 않았다.
- 기존 상태줄·Codex thread usage·일부 Claude 클라우드 보충의 미제공과 Claude 계정 귀속의 부분수집 상태는 배포 전과 같았다. 수동 갱신 완료를 모든 제공사 원본 수신 성공으로 간주하지 않는다. 새 소스 오류나 서비스 실패는 없었다.
