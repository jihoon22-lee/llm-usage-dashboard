# 비용 관점 인사이트

## 요청과 탐색

- 대시보드에 더할 만한 인사이트가 있는지 찾아 검토한다. 브랜치는 `feat/cost-lens`(상단 바 정비 위)다.
- 운영 DB를 읽기 전용으로 열어 최근 30일을 후보별로 계산해 봤다. DB와 설정은 바꾸지 않았다.

| 후보 | 운영 기록에서 본 것 | 판단 |
| --- | --- | --- |

## 변경

- `/api/usage`의 `cost.by_type`: 기간의 환산 비용을 일반 입력·캐시 읽기·출력·캐시 생성으로 나눈 값. 네 값의 합은 `cost.period`와 같고, 단가가 적용된 기록이 없으면 `null`이다.
- `/api/overview`: 상위 모델·프로젝트에 `cost`·`cost_share`, `recent.cost`, 사실 종류 `cost_share`를 더했다. 프로젝트 비용은 요청 기록만 환산하며(서버 누계에는 토큰 유형이 없다) 단가가 없으면 `null`이다. 사실 목록 상한을 6개에서 7개로 늘렸다.
- 개요: 상위 모델·프로젝트 줄에 환산 비용을 병기하고, `비용` 사실을 누르면 그 모델의 최근 30일 사용량으로 이동한다.
- 사용량: 토큰 구성 패널 아래에 비용 구성 막대와 유형별 비중을, 모델 상세 표의 비용 추정 칸에 `1M당` 환산 비용을 더했다.
- 예측·권고는 추가하지 않았다. 모든 값은 기록된 토큰에 공개 단가를 곱한 환산이다.

## 검증

- `tests/test_overview.py`에 세 검사를 더했다: 순위의 비용이 같은 범위의 사용량 탭 비용과 같은지, 단가 없는 사용이 0이 아니라 빈 값인지, 비용 사실이 조건을 만족하는 모델만 고르는지.
- `tests/browser_overview.py`에서 프로젝트·비용 사실을 눌러 이동한 화면의 비용이 개요의 값과 같은지, 비용 구성 막대의 조각 수와 비중 합(100%), 표의 `1M당` 표시를 확인한다.
- `.venv/bin/python -m unittest discover -s tests -q` 595개, 웹 JS 문법 검사, Node 테스트 45개, 합성 데이터 브라우저 스위트 24개 통과.
- 합성 데이터 화면을 1440px·390px로 캡처해 비용 구성 막대, 순위의 비용 표기, `비용` 사실을 확인했다. 토큰 집계는 바꾸지 않아 원본 대조는 다시 돌리지 않았다. 운영 서비스에는 적용하지 않았다.
