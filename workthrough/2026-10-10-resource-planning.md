# 사용 가능 자원·작업 전망 0.2.0

## 요청과 범위

사용자는 한도별 소모 속도, 작업 지속 시간, 오늘·이번 주 전망, 서비스·모델 선택,
초기화권·크레딧의 자동 조회와 수동 기록을 요청했다. 구현 완료 후 문서·버전 갱신,
태그·GitHub Release와 운영 배포까지 승인했다. 시작 main은 `349c5ff`, 공개 버전은
0.1.1이다. 기능 추가에 맞춰 0.2.0으로 올린다.

`feat/resource-planning`의 독립 worktree와 uv 0.12.23 `uv sync --locked` 환경을 사용한다.
운영 가상환경은 배포 시 두 서비스를 정지한 뒤에만 갱신한다. 초기화권 소비,
크레딧 구매·자동 충전 설정 변경, 새 계정 로그인, 외부 알림 테스트 발송은 범위에 없다.

## 사전 시나리오 검토

- 앞선 실제 Chromium 검토: 속도는 상세 안에 숨고, Codex 모델별 소진을 서비스 추천에서
  제외하며, Claude 특정 모델 소진이 서비스 전체 추천을 제거하는 상황을 재현했다.
- 추가 계산 검토: 계정 A→B의 차이를 소비로 처리, 서로 다른 출처의 잔여·속도 결합,
  미래 시각의 기록이 최신값을 막음, 불완전한 로컬 토큰으로 남은 요청 수 환산을 재현했다.
- 추가 Chromium 검토: 주간 한도가 오래됐는데 5시간 한도만으로 추천하고,
  2시간 전 오프라인 사본에 ‘최근 확인’·현재 추천·옛 초기화 카운트다운이 남는 것을 확인했다.
  이 결과는 합성 데이터 재현이며 실제 계정에서 발생한 사고를 뜻하지 않는다.

## 구현과 검증 기록

### 자원·계정·판단 기반

- 추가 테이블에 불투명 계정 식별자, 관측 구간, 자원 종류·단위·출처·확인 시각,
  자동/수동 기록과 수정 버전을 보존한다. 기존 사용 이력은 유지하고 미확인 계정을
  현재 계정으로 소급하지 않는다. 초기화권 원본 ID도 불투명 식별자로 저장한다.
- Codex 크레딧은 모델 버킷마다 반복돼도 한 번만 보존하고, 초기화권 개수는 상세
  목록 길이로 대체하지 않는다. 누락 응답은 이전값을 남기면서 현재 확인 불가로 표시한다.
- Claude의 사용 지출 한도와 선불 잔액을 분리하고, 명시한 통화·소수 단위만 변환한다.
  적용 범위 제한이 있는 잔액을 일반 사용 가능 잔액으로 합산하지 않는다.
- 계정 전환·시계 오차·출처 변경을 다루고, 최근 30분(최소 15분)과 비교 3시간
  (최소 90분)의 관측 속도를 제공한다. 모델별 적용 한도, 일부 오래된 값,
  초기화 전후, 추가 자원 조건을 판단한다. 토큰/요청 환산은 계정 전체 수집 범위를
  입증할 수 없어 현재 작업 전망에 사용하지 않는다.
- 수동 자원 API는 기존 Tailscale 인증·CSRF 보호와 수정 버전 검사를 사용한다.
- 초기 전체 Python 검사 312개 통과. 새 자원·판단·API 시나리오와 기존 회귀를 포함한다.
  소켓 검사는 허용된 독립 검증 환경에서 실행했다. 빈 `.git` 디렉터리를 실제 저장소로
  오인하는 기존 경계도 재현해 유효한 HEAD가 있는 경우만 저장소로 인식하도록 보완했다.

### 실제 제공사 읽기 확인

- Codex CLI 0.162.0의 읽기 전용 `account/rateLimits/read`에서 초기화권 개수·상세와
  크레딧 필드 수신을 확인했다. 대화·인증값·원본 응답은 기록하지 않았다.
- 설치된 Claude Code 2.1.288에서 `/api/oauth/usage`, 추가 크레딧 GET,
  초기화권 조회 GET의 경로와 응답 형식을 확인했다. 기본 계정 메타데이터의
  계정·조직 식별자만 사용하고 이메일·이름·인증값은 저장하지 않는다.
- 실제 계정 읽기에서 추가 사용 조건, 선불 잔액, 초기화권 상태의 응답 수신을 확인했다.
  계정별 잔액·보유 개수·개인 식별값은 공개 기록에 남기지 않는다.
  유료 사용 성공·초기화권 소비를 검증한 것은 아니다. 내부 경로는 변경될 수 있다.
- 이 단계의 읽기 진단과 운영 수집기 배포는 별개다. 이후 실제 배포 결과를 이 기록에 갱신한다.

### 화면·실패 복구·시나리오

- 개요 상단에서 서비스·모델/한도 묶음·작업시간·최근/비교 속도를 선택한다. 한도별
  속도와 조건부 소진 시간은 상세를 열지 않아도 보인다. 초기화 시간표와 계산 근거는
  접고, 오늘·이번 주 전망은 소비 분석의 별도 접이식 영역에 배치했다.
- 크레딧·초기화권·지출 한도를 구분해 표시한다. 연결한 수동 기록은 참고로 접고
  중복 합산하지 않는다. API 전용 수동 기록은 구독 계정 변경과 별도로 유지한다.
- 수동 수정은 버전 충돌 시 입력을 유지한다. 새 기록 저장의 응답이 유실돼도 같은
  요청 ID로 재시도하므로 잔액이 중복 생성되지 않는다. 그 사이 다른 수정이 있으면
  재시도 성공으로 위장하지 않고 최신 기록을 확인하게 한다.
- 오프라인·시간 경과 시 관측값의 상태, 소진 예측, 대안, 초기화 카운트다운을 함께
  갱신한다. 계정 전환을 회복 알림으로 오인하지 않고, 제공사의 사용 제한과 잔여율을
  구분한다. 일부 응답에서 빠진 이전 한도를 최신값으로 남기지 않는다.
- 브라우저 16개 검사 묶음에서 기존 흐름과 새 시나리오를 확인했다. 신규 검사는
  1440/390/320px의 첫 화면 판단·속도 표시, 모델별 제약, 계획 시간 변경, API 크레딧
  분리, 수동 수정 충돌·응답 유실 재시도, 오프라인 경과·재연결을 실제 Flask API로
  검증한다. 화면에 실제 계정 데이터는 쓰지 않는다.
- 운영 DB의 읽기 전용 사본에서 새 테이블 초기화와 실제 계정 읽기를 실행하고,
  기존 events·usage_hourly 합계 보존, Codex 자원 정규화와 원본 값 일치,
  Claude 추가 자원 수신, 응답의 인증정보 미포함을 확인했다. 원본 대조에서도
  Codex 불일치와 Antigravity/Devin 누락·불일치·원본 오류가 없었다.

## 운영 배포 상태

- 운영 DB의 일관된 읽기 전용 사본, 기존 가상환경 아카이브·패키지 목록·이전 릴리스
  경로를 비공개 복구 백업에 보존했다. DB quick_check·환경 파일·복구 릴리스와
  백업 폴더 권한을 확인했다. 백업은 임시 파일 정리에서 제외한다.
- 사용자가 두 서비스를 정지한 뒤 모두 inactive/dead임을 확인했다. 정지 시점의
  최신 DB 사본을 추가 보존하고 uv 0.12.23의 `sync --locked --no-dev`로 운영 환경을
  갱신했다. 프로젝트 메타데이터는 0.2.0으로 바뀌고 외부 의존성은 유지됐다.
- 기존 배포기의 Python 322개·JavaScript 검증, 전환·실패 복귀·재시작 절차를 사용해
  정확한 v0.2.0 커밋 `ebaba1507d8519ed32506c1a59215551c1e87476`을 운영에 적용했다.
  웹·수집기가 모두 active이며 두 프로세스의 실제 작업 디렉터리가 해당 릴리스임을 확인했다.
- loopback health, 재시작 이후 새 수집 heartbeat, 실제 Tailscale 인증 화면의
  데스크톱·모바일 smoke가 통과했다. 추가로 320/390/1440px에서 새 작업·자원 영역의
  표시와 가로 넘침 없음, JavaScript 오류 없음을 확인했다.
- 실제 인증된 자원 API에서 Codex·Claude 크레딧과 초기화권의 최신 관측 및 계정 식별을
  확인했다. 실제 잔액·개수·식별자·인증값·화면은 공개 기록에 남기지 않는다.
- 실제 인증·CSRF 경로의 수동 갱신 요청이 수락되고 동일 요청 ID의 수집 완료와 최신
  heartbeat를 확인했다. 제공사별 대기 정책은 우회하지 않았다.
- **운영 배포 완료.** 수동 자원 쓰기·충돌·오프라인 복구는 앞선 합성 검증 결과이며,
  실제 계정의 구매·초기화권 소비는 실행하지 않았다. 신규 계정 관측의 속도 확보 조건과
  제공사 미제공 필드 등 문서의 제약은 유지한다.

## 후속 수정: 구독 한도 우선·Claude 자원 실수신

사용자가 첫 화면의 우선순위와 실제 보유 자원 누락을 지적했다. 기존 검증은 HTTP 성공과
fresh·계정 식별만 확인했으며, 제공사 화면의 실제 보유 자원과 대조하지 않아 잘못된 0과
수집 대상 누락을 발견하지 못했다. 이 검증 한계를 인정하고 다음을 수정했다.

- 개요 순서를 구독 한도 → 추가 사용 자원 → 지금 작업 → 기간 요약으로 바꿨다.
  320/390/1440px 첫 화면에서 한도 카드가 보이는지 검사하고 합성 문서 화면을 교체했다.
- 초기화권 조회에는 CLI 플랫폼 헤더와 설치된 버전의 CLI User-Agent가 함께 필요했다.
  `eligible=false, ineligible_reason=surface, grants=[]`는 보유 0회가 아니라 조회 경로 제한이다.
  이 응답은 미확인으로 처리하고 이전 관측이 있으면 미확인 상태로 보존한다.
- 일반 OAuth 사용량의 `iguana_necktie` 항목에서 클라우드 세션 프로모션의 원본 달러
  지급액·사용액·잔액·만료를 읽는다. 일반 선불 잔액·추가 사용 활성화·로컬 한도와 분리하고
  로컬 작업 대안에 합산하지 않는다. 누락·금액 불일치·만료도 별도 처리한다.
- 수정한 모듈이 독립 checkout에서 로드됐음을 확인하고 임시 DB에서 실제 조회했다.
  초기화권 수신, 클라우드 자원의 원본 지급액−사용액=잔액과 만료·계정 식별을 대조했다.
  구매·초기화권 소비는 실행하지 않았으며 실제 금액·식별자·원본 응답은 기록하지 않는다.
- Python 329개, 전체 JavaScript 구문·단위 검사, 브라우저 16개 묶음이 통과했다.
  구독 한도의 첫 화면 위치, 초기화권·클라우드 전용 잔액 표시, 로컬 작업 추천 제외,
  기존 편집·충돌·오프라인 회귀를 포함한다. 문서 링크·개인정보 패턴·diff 검사도 통과했다.
- 의존성·프로젝트 버전·DB 토큰 집계 구조는 바꾸지 않는다. 공개 v0.2.0 태그와 파일은
  유지하고 수정 main을 코드 전환으로 운영에 반영한다. 운영 가상환경 재동기화는 필요 없다.
- [PR #24](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/24)의 필수 CI 통과 후
  `397276666becdaa7c7235ad7e1f9a03677c073fb`로 병합하고 기존 배포기로 코드만 전환했다.
  운영 가상환경은 갱신하지 않았다. health·새 heartbeat와 두 프로세스의 실행 경로를 확인했다.
- 배포 이전의 잘못된 정상·0회 초기화권 캐시 한 건은 비공개 백업 후 다음 읽기를 허용했다.
  수정 전 관측·실패 없음·인증 차단 없음·빈 목록/0회 조건을 모두 확인한 일회성 데이터 정정이다.
  오류·429 대기 상태를 지우거나 일반 갱신의 대기 정책을 변경하지 않았다.
- 인증된 운영 화면의 1440/390/320px에서 구독 한도가 추가 자원·작업 전망보다 먼저 보이며
  가로 넘침·JavaScript 오류가 없음을 확인했다. 모바일 기본 요약과 선택 후 상세도 확인했다.
- 운영 수집기의 새 관측과 화면에서 초기화권 실제 보유, 클라우드 전용 지급액·사용액·잔액의
  원본 관계와 만료·계정 식별을 다시 대조했다. 합성 fixture나 HTTP 성공만으로 완료하지 않았다.
  **후속 수정의 운영 반영과 실제 자원 표시 검증을 완료했다.**

## v0.2.1: 자원별 만료일 표시와 릴리스 준비

- 사용자가 Claude 웹의 설정 → 사용량 → 클라우드 세션 크레딧 항목임을 확인하고,
  모든 초기화권·크레딧의 만료일을 함께 보여 달라고 요청했다. 기존 연결 항목과 일치한다.
- 각 초기화권의 만료일을 개별 목록으로, 크레딧의 만료일을 잔액 아래에 항상 표시한다.
  상세를 열지 않아도 연도·날짜·KST 시각을 확인할 수 있다. 일부 잔액의 다음 만료,
  날짜 미제공, 이미 지난 시각과 사용/만료 상태를 구분한다. 지출 한도는 갱신 시각을 표시한다.
- 만료일을 추측하거나 개수·잔액을 시간 경과만으로 다시 계산하지 않는다. 기존 원본 필드와
  수동 기록을 표시하며 만료 정보 미제공은 무기한 사용 가능을 뜻하지 않는다.
- 합성 브라우저 검증에서 320/390/1440px의 개별 날짜·미제공·부분 만료·과거 만료와
  수동 기록 만료일을 확인했다. `<time>`의 원본 시각과 표시 날짜를 대조하고 상세가 닫힌
  상태에서도 보이는지 검사했다. 사용 안내에 실제 계정이 없는 합성 자원 화면을 추가했다.
- 최종 Python 329개, JavaScript 구문·단위 검사, 브라우저 16개 묶음 통과.
  wheel/sdist 파일·메타데이터·웹 자산 해시, 소스 밖 wheel 설치와 신규 태그 checkout 설치 통과.
- README·설치·운영·사용 안내와 변경 기록을 갱신하고 프로젝트·lock 버전을 0.2.1로 맞췄다.
  외부 의존성은 0.2.0과 완전히 같다. 앞선 구독 한도 우선 배치·Claude 자원 수신 수정도 포함한다.
- PR/main·태그·릴리스·운영 배포는 검증 완료 후 진행한다. 버전 메타데이터를 포함한 운영
  환경 동기화 전에 두 서비스를 정지해야 하며, 기존 공개 태그와 릴리스 파일은 변경하지 않는다.
