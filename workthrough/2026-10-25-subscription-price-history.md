# 구독료 변경 이력과 요금제 변경 전 한도 관측

## 요청과 확인

- Codex 구독료를 $220에서 $110으로 낮춘 직후, 리포트의 구독 가치 배수가 두 배로 뛰고 한도 탭 Codex 카드에 '이전 관측'이 생겼다. 원인을 검토하고 권장 처리, 버전 갱신, 운영 배포까지 진행했다.
- 작업 시작 시 main은 `1831a6f`(v0.9.1)였다. 별도 worktree와 uv 0.12.23의 잠긴 환경에서 작업했다.
- 구독 가치는 기간 환산 가치를 **현재** 월 구독료 하나로 나눴다(`store.py`의 `monthly_equiv / monthly_usd`). 구독료 이력이 없어서 내리면 과거 사용 가치가 부풀고, 올리면 줄었다. 운영 DB 사본에서 확인한 Codex 배수는 ÷$110 기준 7일 187.9배 · 30일 141.9배 · 전체 79.8배, 시간 비례 기준 94.0 · 71.0 · 39.9배였다.
- 월간 결산은 처음 결산할 때의 구독료로 고정된다. 그대로 두면 11/1에 10월 전체가 $110으로 결산돼 영구히 두 배로 남는다. 6~9월 결산은 10/24에 한꺼번에 다시 만들어져 당시 설정값 $220이 들어가 있다(관측 이력이 아니라 당시 설정값).

## 변경 1: 구독료 이력과 시간 비례 분모

- 개인 설정에 `subscription_price_history`(`{route: [{until, usd}]}`)를 추가했다. 현재 구독료는 기존 `subscription_prices`에 그대로 두고, 이전 구독료만 언제까지 적용됐는지와 함께 남긴다. 이력이 없으면 현재 구독료가 전체 기간에 적용돼 동작이 이전과 같다.
- 설정 저장 시 바뀐 구독료의 적용 시점을 고른다: 지금부터(기본) · 지정한 시각부터(KST) · 현재 구독료 정정 · 전체 기간. 값이 바뀌지 않은 구독은 어느 방식이든 이력을 유지하고, 구독료를 비우면 이력도 지운다. 깨진 이력 항목은 무시한다.
- 구독 가치의 분모는 기간 안 구독료를 적용 시간에 비례한 평균(`effective_usd`)이다. 구독료가 기간 안에서 바뀌었다면 구간별 환산·토큰(`price_segments`)을 함께 주고, 화면은 행 아래에 구간별 구독료·환산·배수를 표시한다. 하루 미만 구간은 배수를 생략한다. 시간 단위 롤업이라 변경 시각이 들어 있는 1시간은 그 시간이 시작된 구간에 넣는다. 구간별 표시는 여러 Claude 계정으로 나뉜 경우에는 생략하며 분모는 그대로 적용한다.
- 월간 결산은 같은 평균을 `monthly_usd`로, 월말 구독료를 `list_usd`로, 그 달에 쓴 이력을 `price_history`로 저장한다. 다시 계산할 때는 저장된 구독료와 이력을 쓰므로 나중의 설정 변경이 결산을 바꾸지 않는다. 이력 없이 저장된 과거 결산은 그대로 유지된다. 결산 형식 번호는 올리지 않아 기존 결산을 다시 만들지 않는다.
- 실제 청구(일할·크레딧·다음 결제일 적용)와 다를 수 있다는 설명을 화면·사용법·README에 추가했다.

## 검증

- 독립 환경에서 Python 561개(새 구독료 이력 12개 포함), 웹 JavaScript 전체 문법, Node 42개 검사를 통과했다.
- 새 단위 검사: 적용 시점별 이력 변경, 같은 값 유지, 0 길이 구간, 이전 값으로 복귀, 깨진 항목, 기간 경계별 평균, 구간 합계가 기간 환산·토큰과 일치하는지, 응답 캐시 키, 월간 결산의 비례 평균과 재계산 고정, 이력 없는 과거 결산 유지, API의 지정 시각·잘못된 모드·미래 시각 거부, 이름·구독 종료와 함께 저장.
- Chromium 합성 검사 `browser_claude_accounts`·`browser_insights`·`browser_smoke`를 통과했다. 설정에서 지정 시각 입력 표시/누락 안내/저장, 이전 구독료 표시, 리포트의 기간 평균·구간별 배수·1일 미만 생략을 1440px·390px에서 확인했다. 합성 API 검사이며 운영 화면 확인과 구분한다.

## 변경 2: 계정·요금제 변경 전 한도 관측

- 운영 한도 이력: 10/25 21:17까지 이전 요금제 주간 창 0%(소진), 21:23~22:35에는 응답에 `43200분`(30일) 창 100%만 왔고 초기화가 매번 조회 시각+30일로 밀렸다(시작 전 창). 22:46:51 새 요금제가 관측되며 계정 epoch가 바뀌고 주간 창이 100%로 새로 시작됐다. 한도를 잘못 받은 것이 아니라 전환 중 받은 창이 정리되지 않은 것이다.
- 기존 동작: '최근 계정 응답에서 확인하지 못함' 안내가 계정 변경 안내보다 먼저 판정됐고, 다음 초기화에 30일 창이 들어갔으며, Codex 상태가 '일부 오래됨'이 됐다. Codex 한도 행은 지워지지 않아 9/18의 `codex_bengalfox` 모델 창 2개도 같은 이유로 남아 있었다.
- 이전 epoch의 행이 새 epoch 계정 응답에 없으면 `retired`로 표시한다. 안내는 계정·요금제 변경 전 관측임을 말하고, 카드에서 '계정·요금제 변경 전 관측 N개'로 접어 현재 한도·다음 초기화·'일부 오래됨' 판정에서 뺀다. 관측 중단 접기 기준(기본 7일)이 지나면 카드에서 숨긴다. API와 DB의 행은 유지한다. 같은 요금제 안에서 응답에 빠진 창은 기존 '이전 관측' 그대로다.
- 검증: 전환 순서(pro 주간 → 전환 중 30일 → 새 요금제 주간)와 같은 요금제 누락을 단위 검사로 고정했다. `Store.limits()`로 만든 fixture의 Chromium 1440px·390px에서 접힘·다음 초기화 제외·개요 '최근 확인'을 확인했다. main 통합 후 Python 563개·Node 42개·브라우저 4개 스위트를 다시 통과했다.
