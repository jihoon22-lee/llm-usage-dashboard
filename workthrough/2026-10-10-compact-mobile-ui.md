# 개요 화면 압축·초기화 일정 복원

## 요청과 범위

사용자는 0.2.x에서 추가된 초기화권·추가 크레딧 카드가 불필요하게 커서 모바일에서 보기 불편하고,
원래 바로 보이던 다음 초기화 일정이 접힌 상태가 기본이 된 점을 지적했다. 전체 디자인·사용성
개선과 그에 따른 기능 정리를 함께 요청했다. 시작 main은 `ec5df22`(0.2.1)이다.

`feat/compact-mobile-ui`의 독립 worktree와 uv 0.12.23 `uv sync --locked` 환경을 사용했다.
수집·집계·API·의존성·프로젝트 버전은 바꾸지 않는다. 운영 배포는 이번 요청 범위에 없다.

## 변경 전 확인

합성 자원 시나리오(`tests/browser_resource_planning.py`와 같은 데이터)를 실제 Flask 앱으로 띄워
390/1440px 화면을 확인했다.

- 다음 초기화 시간표는 `0.2.0`의 `bdf065a`에서 `<details>`로 접혔다. 모바일 한도 목록은
  잔여율만 보여 초기화 시각을 보려면 서비스 카드나 시간표를 열어야 했다.
- 자원 카드 하나가 모바일에서 330–600px였고, 개요 전체 높이는 3870px였다. 서비스 이름이
  카드 머리와 제목에 두 번 나오고, 확인 시각·적용 범위·조건이 각각 별도 줄이었다.
- 모바일 상단은 브랜드와 같은 의미의 h1·갱신 버튼이 별도 줄로 약 190px를 차지했다.
- 수집 상태 카드는 이름·상태·설명·확인 시각을 각각 한 줄씩 썼다.

## 구현

- **다음 초기화**: 접기를 없애고 구독 한도 목록과 서비스 카드 사이에 항상 표시한다. 7일 축은
  유지하고 행은 `라벨 — 남은 시간 · 시각` 한 줄로 줄였다. 데스크톱은 여러 열 격자로 놓는다.
  소진 중인 한도의 남은 시간은 경고색으로 표시한다.
- **모바일 한도 목록**: 한도마다 `5h 40.0%  3시간 59분`처럼 잔여와 초기화까지 남은 시간을
  한 줄씩 보여 주고 잔여 수준을 색으로 구분한다. Antigravity 묶음 형식은 유지했다.
- **추가 사용 자원**: 제목(서비스 태그+이름)과 값을 한 줄에 두고, 만료는 짧은 KST 날짜와
  남은 시간을 함께 표시한다(다른 해일 때만 연도). 적용 범위와 사용 조건을 한 줄로 합치고
  확인 시각은 근거 요약으로 옮겼다. 정상 자동 조회는 배지를 생략하고 그 외 상태만 배지로
  표시한다. 초기화권은 회수·만료·대상·사용 조건을 한 행에 두고 사용·만료된 권은 흐리게 한다.
  모바일에서는 한 목록 안에 구분선으로 나열한다.
- **기타**: 모바일 h1은 화면에서 숨기고(스크린 리더 유지) 갱신 상태·버튼을 한 줄로 배치했다.
  ‘지금 작업’의 확인 버튼은 직접 입력 작업시간일 때만 보인다(나머지는 변경 즉시 적용).
  기간 요약·수집 상태 카드를 압축하고 수집 범위 설명 글자 크기를 맞췄다. 접는 패널은 모든
  폭에서 ＋/− 표시를 보이며, 캐시 활용률 분석도 같은 머리 형식을 쓰되 데스크톱 기본 닫힘은 유지한다.
- `format.js`에 짧은 남은 시간 `soon`과 KST 날짜 `stamp`를 추가하고 단위 테스트를 붙였다.

변경 후 같은 합성 화면에서 모바일 개요는 3870px → 약 2820px, 자원 영역은 약 2300px → 약
1060px, 자원 행은 125–165px(초기화권 3개 행 240px)이다.

## 탭 재구성

탭을 `한도·계획·사용량·리포트·상태` 다섯 개로 나누고 설정을 헤더로 옮겼다(뷰 이름 `quota·plan·usage·reports·status`).

| 패널 | 이전 | 이후 |
|---|---|---|
| 구독 한도·다음 초기화·추가 사용 자원(수동 기록 양식 포함) | 개요 | 한도 |
| 지금 작업(`#work-now`) | 개요 | 계획 |
| 오늘·이번 주 작업 전망(`#work-budget`, 한도별 예상 잔여 표) | 소비 분석의 접는 `<details>` | 계획 · 항상 펼친 패널(`#work-budget-open` 단추·핸들러 삭제) |
| 기간 요약(`#cards`) | 개요 | 사용량 · 필터 바로 아래(`#cards-edit` 단추·핸들러 삭제) |
| 필터·사용 간극·추이·토큰 구성·시간 패턴·모델 표 | 소비 분석 | 사용량 |
| 프로젝트별·세션별 사용량, 이전 기간과 비교, 캐시 활용률 | 인사이트 | 사용량(`data-panel` 추가: `comparison`) |
| 주간 리포트·일별 활동·구독 가치 | 인사이트 | 리포트 |
| 수집 범위·수집원 상태 | 수집 상태 | 상태(`#sources-panel`은 안쪽 패널로 유지) |
| 데이터 신뢰도(`#quality`) | 인사이트 | 상태 |
| 알림 발송 이력(`#notify-log`) | 설정의 외부 알림 안 | 상태(전송 설정·테스트는 설정에 유지) |
| 이 기기의 오프라인 통계 | 설정 | 상태 |
| 테마 선택(`#theme`) | 헤더 | 설정 맨 위 |

- **동작**: `setView`가 별칭 맵(`overview→quota, analysis→usage, insights→reports, sources→status`)을
  거쳐 URL·저장된 마지막 화면·경고 칩의 이름을 모두 변환한다. 프로젝트 예산 경고 칩은 표가 있는
  사용량으로 간다. 설정은 `previousView`를 기억해 ‘← 돌아가기’로 복귀하며, 저장되는 마지막 화면은
  설정이면 직전 탭이다. 설정이 열려 있으면 어떤 탭도 선택되지 않는다(`aria-selected` 전부 false).
- **인사이트 로딩**: `INSIGHT_VIEWS=['usage','reports','status']`에서 `loadInsights()`를 호출한다
  (필터 변경·갱신 후에도 같은 탭이면 이어서 불러온다). 리포트 탭은 `loadReports()`, 상태 탭은
  `loadNotifyLog()`를 호출한다. 알림 이력은 설정 로드와 분리해 `settingsOnline` 조건을 뺐다.
  `#insights-status` 배너는 `body[data-view]`가 위 세 탭일 때만 보인다.
- **패널 순서**: `applyPanelOrder`는 각 탭이 가진 id만 따라 재배열하므로 예전 `llmOrder`의 다른 탭 id가
  패널을 옮기지 못한다. 사용량·리포트에 `순서` 토글을 둔다.
- **단축키**: `1`~`5` 다섯 탭, `,` 설정, `?` 도움말 문구 갱신. `#context-bar`(핀 고정 필터 요약)는
  필터가 사용량 탭 안으로 들어와 코드·CSS와 함께 삭제했다.
- **모바일**: 하단 막대 다섯 탭(두 글자). 리포트·일별 활동은 이 탭의 주 내용이라 모바일에서도 기본 펼침이다.
- **알려진 점**: 구독 가치의 ‘기간 환산’은 서버가 사용량 필터 기간으로 계산해 필터를 따른다(리포트 탭에 있어도
  필터 비의존이 아님). 사용량 탭은 필터 변경 후 인사이트 응답까지 갱신 버튼이 바쁨 상태로 남는다
  (이전 인사이트 탭과 같은 동작이 사용량 탭으로 옮겨옴).

## 편의 기능

한도·계획 탭 위에 얹은 다섯 가지 변경이다. 서버·API는 바뀌지 않았다.

- **수동 자원 기록 대화상자**: `#resource-editor` 폼을 `<dialog id="resource-dialog">`(`main` 밖, `.shell` 끝)로 옮겼다. 폼과 모든 id·저장·409 재조회·요청 id 재시도·오프라인 동작은 그대로이다. `editResource()`가 `showModal()`을 호출하고, 닫기 단추·Esc(`cancel` 이벤트에서 `preventDefault`)·`closeResourceEditor()`가 같은 경로를 쓴다(저장 중 차단, 입력이 있으면 `confirm`). 닫으면 연 단추(수정 단추, 다시 그려졌으면 `#resource-add`)로 포커스를 돌려준다. 데스크톱은 640px 가운데 패널, 600px 이하는 아래 시트(전폭·`max-height:90vh`, 본문 스크롤, 작업 줄 `position:sticky`). 메시지 줄은 스티키 작업 줄 위로 옮겼다. 모달이 열려 있으면 `1`~`5`·`,`·`r` 단축키는 무시한다.
- **만료 임박 알림**: `format.js`의 순수 함수 `expiringResources(items,now,within=86400)`가 24시간 안에 끝나는 잔액·초기화권을 고른다(이미 지난 것·`used/expired` 초기화권·잔액 0·이전 계정·연결된 중복·지출 한도(갱신일)는 제외, 같은 시각(1시간)에 끝나는 초기화권은 개수 합산). `renderAlerts`가 `Codex 초기화권 1개 59분 후 만료`·`Claude 사용 크레딧 50 USD …`·`일부 잔액` 칩을 만들고, 누르면 한도 탭으로 가서 `[data-resource-id]` 카드로 스크롤한다. 확인이 오래된 기록의 칩에는 `확인 오래됨`을 붙인다. 설정의 알림 항목에 `자원 만료 임박`(`ntf-exp`, 기본 켜짐)을 더했고 `checkExpiryNotify`가 오프라인 사본·오래된 기록은 건너뛰며 초기화권 id(또는 자원 id+만료 분)별로 한 번만 보낸다. 이 브라우저의 `localStorage`(`llmExpiryNotified`)에도 남겨 새로고침 후 반복하지 않는다.
- **계획 한 줄 요약**: 한도 탭 맨 위 `#plan-summary` 단추(`renderPlanSummary`, `renderWorkPlan`에서 호출). 상태는 계획 탭이 쓰는 `lastLimits.planning`과 같고 `unknown`·오프라인·관측 오래됨·불러오기 실패는 `판단 보류 — …`로 표시하며 시간·대안을 내지 않는다. 계획 데이터가 없으면 숨기고, 누르면 `setView('plan')`. 데스크톱 한 줄(말줄임), 600px 이하 최대 두 줄.
- **앱 바로가기**: `manifest.json`에 `shortcuts`(`/?view=quota`·`/?view=plan`, 192px 아이콘). 매니페스트 해시는 `scripts/check_package.py`가 파일 내용으로 계산하므로 코드 수정은 필요 없었고 `sw.js`는 매니페스트를 가로채지 않는다.
- **계획 탭 간격**: `.work-now` 아래 여백(26→16px, 모바일 6px)과 `.plan-evidence`·`.work-followup` 여백을 줄여 판단 근거 줄과 작업 전망 패널 사이의 빈 띠(약 47px→24~28px, 접힌 줄 높이 포함)를 줄였다. 600px 이하에서 작업 전망 제목 오른쪽 요약은 `flex-wrap`으로 제목 아래 전폭으로 내려간다.

  - `browser_resource_planning`: 3개 폭에서 대화상자 `:modal`·라벨 입력 포커스·데스크톱 640px 가운데/모바일 아래 시트·가로 넘침 없음·저장 단추 가시, Esc 취소 시 `confirm` 거절하면 유지·수락하면 닫힘, 닫은 뒤 `#resource-add`(수정 단추로 열었을 때는 그 단추)로 포커스; 한 시간 뒤 만료되는 Codex 초기화권 칩(2일 뒤·이미 지난 것은 칩 없음)과 칩 클릭 시 한도 탭의 해당 카드가 화면에 들어옴; `#plan-summary`의 부족 예상 문구·대안·높이(한 줄/두 줄 이하)·클릭 시 계획 탭, 오프라인 재현에서 `판단 보류`로 바뀌고 시간·대안이 사라졌다가 복구 후 되돌아옴; 매니페스트 바로가기 두 개와 각 URL이 해당 탭을 염; 계획 탭 간격과 작업 전망 요약 위치.
  - `browser_notifications`: 만료 임박 알림이 한 번만 가고(새로고침·메모리 집합 초기화 후에도) 설정을 끄면 안 가며 계획 데이터가 없으면 `#plan-summary`가 숨겨짐. 기존 테스트의 forecast 잔여 값이 렌더를 깨뜨리던 것을 만료 단계 전에 비웠다.
  - 기대값 갱신: `browser_insights`의 제목 목록에서 `수동 자원 기록`(이제 `main` 밖), `browser_smoke`의 알림 토글 6→7개.
