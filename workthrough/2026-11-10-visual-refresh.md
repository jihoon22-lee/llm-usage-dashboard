# 상단 바 통합과 시각 체계 정비

## 요청과 판단

- 대시보드를 더 현대적이고 깔끔하게, 필요한 정보는 그대로 전달하도록 개선한다. 작업 시작 시 main은 `6a8d1a2`, 브랜치는 `feat/visual-refresh`다.
- 운영 화면 여섯 뷰를 1440px·390px·어두운 테마로 읽기 전용 캡처해 검토했다(GET 요청만, 같은 출처만 허용, 캡처는 임시 폴더에 두고 작업 후 삭제).
- 탭 구조와 기능은 0.11.0에서 정리한 그대로 두고, 화면 틀과 시각 체계만 손봤다. 검토에서 구조를 바꿔야 할 문제는 나오지 않았다.

## 찾은 문제

- 내용이 시작되기 전에 네 줄(브랜드, 갱신, 알림 칩, 탭)이 쌓여 1440px에서 약 270px를 썼다.
- 개요의 기간 타일이 왼쪽 한도 패널보다 낮아 오른쪽 아래가 비었고, `눈에 띄는 점` 패널과 차트 패널의 높이가 달랐다.
- 한도 탭 `다음 초기화`의 시각 열이 좁아 `22시간 53분 · 11. 11. 12:00` 같은 값이 패널 오른쪽 밖으로 나갔다.
- 낮은 잔여를 뜻하는 막대가 글자용 갈색(`--warning-ink`)이라 탁하게 보였다.
- 모서리 반경이 7·9·10·11px로 섞여 있었고, 표 머리글이 채운 띠여서 숫자보다 무거웠다.

## 변경

- 브랜드, 탭, 갱신 시각과 `지금 갱신`, 데이터 상태, 설정을 한 줄의 고정 상단 바로 합쳤다. 601~1000px에서는 탭이 둘째 줄로 내려가고, 휴대폰에서는 지금처럼 탭이 아래 고정 막대이며 갱신 줄이 브랜드 아래에 온다. 1440px에서 내용 시작 위치가 약 120px로 올라왔다.
- 반경을 `--radius-lg`(패널 14px), `--radius`(타일 10px), `--radius-sm`(버튼 8px) 세 단계로 정리했다. 기간 타일은 테두리 없이 옅은 바탕만 쓴다.
- 한도 막대·링·초기화 점은 새 `--meter-mid`·`--meter-low` 색을 쓰고, 숫자 글자는 대비를 위해 기존 색을 유지한다.
- 표 머리글은 바탕 띠 대신 아래 선으로 구분한다.
- 개요의 타일은 한도 패널 높이에 맞춰 늘어나고 차트와 `눈에 띄는 점` 패널의 높이가 같다.
- `다음 초기화`의 시각 열을 넓혀 값이 패널 안에 들어온다.
- 글꼴 순서를 Pretendard 우선으로 바꿨다. 웹폰트는 내려받지 않으며 설치된 글꼴만 쓴다.
- 쓰이지 않던 `.heading`·`.eyebrow`·`.private` 규칙을 지웠다. API·집계·수집은 바꾸지 않았다.

## 검증

- `node --check`(웹 JS 전체), `node --test 'tests/js/*.test.mjs'` 45개 통과.
- 합성 데이터 브라우저 스위트 24개(`tests/browser_ci.py`의 목록) 전부 통과.
- 운영 API 응답 위에 새 화면 자산만 바꿔 끼운 미리보기(GET 전용)를 1440px·820px·390px와 어두운 테마로 확인했다. 여섯 뷰 모두 가로로 넘치는 요소와 콘솔·CSP 오류가 없었다. 운영 서비스에는 적용하지 않았다.
