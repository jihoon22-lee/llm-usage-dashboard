# 대시보드 가독성과 인사이트 개편

## 요청과 확인

- 화면이 난잡하고 읽기 어렵다는 의견에 따라 디자인 중심으로 전체를 검토했고, 검토 권장안을 모두 구현하기로 했다. 대시보드는 검토 문구보다 관측된 사용량과 인사이트를 먼저 보여 줘야 한다.
- 작업 시작 시 main은 `f413ce5`(v0.10.0)였다. 단계마다 `origin/main`에서 만든 별도 worktree와 uv 0.12.23의 잠긴 환경에서 작업하고, PR·필수 CI·merge commit으로 병합한다. 운영 배포는 이번 범위에 포함하지 않는다.
- 결정한 방향:
  - 기본 화면은 새 `개요` 탭이다. `상태` 탭은 머리글의 데이터 상태 표시와 `진단` 화면으로 옮긴다.
  - 인사이트는 관측값만으로 쓴다. 0.4.0에서 제거한 예측·균등 소비 기준선을 되살리지 않으며, 다른 계정은 사실만 표시하고 전환을 권하지 않는다.
  - 월말 예상은 경과 7일 미만이면 숨기고, 가치 알림은 계속 동작한다.
- 검토 정정: 리포트 탭이 `/api/usage`를 중복 호출한다는 검토 지적은 사실이 아니었다. 두 요청은 `sections=core`와 `sections=insights`의 서로 다른 응답이다.
- 단계: 1 표시 결함 수정 → 2 개요 탭·인사이트 → 3 문구·위계 정리 → 4 차트 색상 체계 → 5 백엔드 캐시·주간 한도 사용량.

## 1단계: 표시 결함 수정

### 변경

- 주간 한도가 소진돼 막힌 5시간 창은 큰 숫자로 `사용 불가`를 먼저 보여 주고, 창 자체의 잔여는 작은 글씨로 둔다. 막대는 비운다. 현재 관측된 0%는 카드와 초기화 목록 모두 `소진`으로 표시한다.
- 다음 초기화는 공통 7일 눈금 아래에 창마다 한 줄씩 표시하고, 각 줄에 자기 표식을 둔다. 여러 표식이 한 줄에 겹치던 문제를 없앴다. 모바일에서는 눈금을 숨기고 이름과 남은 시간만 남긴다.
- 알림은 심각도(`critical`·`warning`·`info`) 순으로 정렬한다. 색상과 함께 `●`·`▲`·`i` 표식을 붙여 색만으로 구분하지 않는다. 접힌 모바일 알림 버튼은 가장 심각한 항목의 색을 따른다.
- 기간 카드의 보조 설명을 별도 줄로 분리했다. 한국어 줄바꿈은 단어 단위(`keep-all`)로 바꿨다.
- 모델 순위 막대가 추이 차트 범례와 같은 서비스 색을 쓴다. 이전에는 같은 색이 화면마다 다른 서비스를 뜻했다.
- 모델 표는 데스크톱에서도 토큰 세부 열을 접은 상태로 시작한다. `상세 열` 선택은 이 기기에 저장된다.
- `모델별 증감`(이전 이름 `이전 기간과 비교`)은 모델별 변화를 먼저 보여 주고, 세부 요청 기록 합계는 한 줄로 줄였다. 구간 시각은 툴팁으로 옮겼다.
- 한도 소비 차트는 항목이 8개를 넘으면 상위 7개만 색을 주고 나머지는 회색 `기타`로 묶는다. 세로축 최댓값은 읽기 쉬운 눈금 단위로 올린다.
- 토큰 구성 범례는 줄인 숫자로 표시한다. 리포트는 첫 응답 전까지 `불러오는 중`을 표시한다.

### 검증

- 독립 환경에서 Python 563개, 전체 웹 JavaScript 문법, Node 42개 검사를 통과했다.
- 새 `browser_readability.py`를 포함한 합성 브라우저 23개 스위트를 모두 통과했다. 새 검사가 확인하는 항목:
  - 막힌 창의 표시
  - 초기화 줄별 표식과 눈금 정렬
  - 알림 심각도 순서
  - 순위 막대와 범례의 색 일치
  - 모델 표 기본 너비와 선택 저장
  - 증감 표시 순서
  - 소비 차트 색 접기
  - 리포트 로딩 문구
  - 390px 가로 넘침 없음
- 모델 표 세부 열이 데스크톱에서도 기본으로 숨겨지므로, 기존 `browser_dashboard.py`의 정렬 검사는 `상세 열`을 켠 뒤 진행하도록 바꿨다.
- 1440px·390px 화면을 직접 확인했다. 전체 페이지 캡처에서 고정 탭바가 중간에 찍히는 것은 캡처 방식 때문이며 화면 결함이 아니다.
- 합성 API 검사이며, 실제 운영 화면 확인과는 구분한다.

## 2단계: 개요 탭과 인사이트

### 변경

- 새 기본 화면인 `개요` 탭을 추가했다. 구성:
  - **지금 쓸 수 있는 한도**: 서비스마다(Claude는 계정별, Antigravity는 모델 묶음별) 가장 빠듯한 현재 창을 한 줄로 표시한다.
    - 소진된 창이 있으면 `사용 불가`와 그 창의 초기화까지 남은 시간을 표시한다.
    - 현재값이 없으면 `이전 N%`와 확인 시각만 표시한다.
    - 한도 탭과 같은 서비스 순서와 관측 중단 접기 규칙(`serviceGroups`)을 쓴다.
  - **기간 타일**: 오늘, 이번 주(직전 같은 시점 대비), 최근 30일, 지난달 구독 가치.
    - 월 누적값과 월말 예측은 표시하지 않는다. 구독 가치는 정산이 끝난 지난달 결산에서 가져온다.
  - **최근 30일 서비스별 사용량** 누적 막대: 하루를 정할 수 없는 계정 누계는 `날짜 미배분`으로 합계에만 넣는다.
  - **눈에 띄는 점**: 기록된 사실만 보여 준다. 예측·기준선·전환 권고는 없다.
    - 지난주 한도 소진 횟수와 연속 주
    - 0% 유지 시간
    - 서비스별 변화
    - 최근 30일 사용 기록이 없는 구독. 수집 경로가 없으면 `수집된 기록 없음`으로 구분한다.
    - 지난달 환산 가치가 구독료보다 낮은 구독
    - 유난히 많이 쓴 날·시간대
  - **최근 30일 상위 모델·프로젝트**
- `/api/overview`(`llm_usage/overview.py`)는 오늘·이번 주·최근 30일을 모두 `Store.usage()`로 읽는다. 그래서 사용량 탭의 같은 기간 카드, 직전 비교, `model:`·`project:` 범위 합계와 같은 숫자다.
  - 세 기간이 서버 누계 대조 결과 하나를 함께 쓰도록 `held()` 안에서 계산한다.
  - 프로젝트 합계는 사용량 탭의 `project:` 범위와 같은 SQL 식에 범위 안의 보완 누계를 더한다. 계정 차이분은 모델·프로젝트에서 뺀다.
- 타일·막대·순위를 누르면 같은 기간과 범위의 사용량 탭으로 이동한다. 한도 행은 해당 한도 카드로, 사실은 리포트·해당 날짜로 이동한다.
- 서비스 단위 수치(차트, 서비스 변화, 모델 서비스명)에는 계정 이름을 붙이지 않는다. Claude 계정 단위 항목은 현재 대시보드에 설정된 이름을 우선한다.
- 탭은 개요·한도·사용량·리포트·상태 다섯 개이고 단축키는 `1`~`5`다.
  - 개요는 주소에 `view`를 남기지 않는다. 예전 `overview` 별칭은 이제 개요로 열린다.
  - 개요가 생기기 전에 저장된 탭 선택은 한 번만 개요로 열고, 이후 선택은 유지한다.
- 오프라인 통계 사본 경로에 `/api/overview`를 추가했다. 패키지 자산 목록과 README·사용 안내도 갱신했다.

- 새 `browser_overview.py`가 확인하는 항목:
  - 기본 화면
  - 막힌 창의 `사용 불가`, Antigravity 묶음별 행, 막대 비율
  - 타일, 사실 문장, 금지 표현 없음

  - 프로젝트 행과 오늘 타일이 사용량 탭의 같은 합계로 이동
  - 저장된 기본 화면의 1회 이동
  - 오프라인 사본
  - 390px 넘침 없음과 하단 탭 5개

  - 이 확인에서 서비스 단위 수치에 원래 Claude 계정 이름이 붙는 문제를 찾아 고쳤다.
  - 이 확인은 운영 서비스 전환이 아니다. 복사본과 화면은 커밋하지 않고 지운다.
- 알려진 제약: 같은 복사본에서 `/api/overview`가 1.2~1.6초 걸린다.
  - 주된 원인은 요청마다 다시 계산하는 서버 누계 대조(약 0.5초), 기록 출처 분류 쿼리, 직전 비교다.
  - 이 비용은 기존 `/api/usage`에도 있다. 5단계 캐시 작업에서 줄인다.
  - 그전까지 개요는 별도 요청으로 지연 로딩되고 다른 화면의 로딩을 막지 않는다.

## 3단계: 문구·위계 정리

### 변경

- **상태 탭 → 데이터 상태와 진단**
  - 탭은 개요·한도·사용량·리포트 네 개다.
  - 머리글의 데이터 상태 버튼은 `수집 정상`·`일시 실패 N`·`조치 필요 N`·`오프라인 사본`·`갱신 실패`를 기호와 글자로 표시한다. 누르거나 `5` 키를 누르면 진단 화면이 열리고, `← 돌아가기`는 직전 탭으로 돌아간다.
  - 예전 `?view=status`·`sources` 주소는 진단으로 연결한다.
  - 머리글 표시와 진단의 묶음은 같은 규칙(`sourceProblems`)을 쓴다. 실패는 외부 알림과 같은 30분 기준이다.
  - 상단 알림 줄의 수집원 칩을 없앴다. 수집기가 멈추면 쓰는 경로마다 `수집 지연` 칩이 20개 가까이 뜨던 문제가 사라졌다. 이제 수집기 경고 줄 하나와 머리글 상태만 남는다.
  - 진단의 수집원 구성:
    - `조치 필요`·`일시 실패`는 카드로 보여 준다.
    - `일부만 확인`·`지금 수집하지 않는 경로`는 짧은 목록이다.
    - `정상`은 접혀 있다.
  - 미제공·미사용 경로는 접지 않는다. 수신하지 못한 상태를 숨기지 않는다는 기준 때문이다. 상태별 안내 문구는 묶음마다 한 번만 쓴다.
  - 데이터 신뢰도는 숫자 타일 대신 항목·값·처리 세 열의 표다.
- **글자 크기**
  - 글자 크기 선언 215개를 12·14·16·20·32px 다섯 단계(`--fs-xs`~`--fs-xl`)로 정리했다.
  - 실제 데이터에서 12px 이하 글자의 비중(1440px):

    | 화면 | 정리 전 | 정리 후 |
    |---|---|---|
    | 사용량 | 95% | 41% |
    | 리포트 | 99% | 14% |
    | 한도 | 89% | 56% |
- **설명 문구 → ⓘ**
  - ⓘ로 옮긴 문구:
    - 패널 아래 설명 13개
    - 비용 카드의 단가 확정 비율
    - 한도 카드의 조회 경로
    - Claude 계정의 로그인 위치
  - ⓘ는 마우스·포커스·탭으로 공용 툴팁을 연다. 버튼의 접근 가능한 이름에도 같은 문구가 들어간다.
  - 접히는 패널의 ⓘ는 `<summary>` 밖에 둔다. 토글 안에 다른 컨트롤을 넣지 않기 위해서다. 화면에는 제목 줄의 설명 문구와 접힘 표시 사이에 그린다.
  - 값을 읽는 방식이 달라지는 문구는 그대로 보인다. 비교할 기록 부족, 이전 구간 0토큰이 그 예다.
  - 패널 머리의 메타 문구는 범위만 남기고 줄였다.
- **주간 리포트**
  - `/api/reports`가 저장된 주마다 그 주의 사실(`week_facts`)을 붙인다. 사실은 한도 소진, 0% 유지 시간, 서비스 변화다. 리포트는 이 사실을 맨 위에 문장으로 보여 준다.
  - 개요의 사실 문장은 최신 리포트가 지난 완료 주일 때만 `지난주`라고 쓴다. 그렇지 않으면 `10월 12일 주`처럼 쓴다.
  - 상위 모델·계정별·상위 프로젝트·세부 줄은 라벨과 값이 정렬된 목록으로 바꿨다. 월간 결산도 같다.
  - 관측됐지만 소진도 0% 시간도 없는 한도 창은 표 안에 둔 채 `소진·0% 시간 없는 한도 N개`로 접는다.
    - 미관측 창은 늘 보인다.
    - 소진·0% 시간이 있는 창이 하나도 없으면 접지 않는다.
    - 실제 데이터의 지난주 표는 11행에서 3행과 접힌 8개로 줄었다.
  - 한도 활용 표의 Claude 계정 이름은 사실 문장·계정별 줄과 같은 규칙으로 맞췄다. 설정한 이름이 우선이다.
    - 실제 데이터 확인에서 같은 계정이 사실에는 `Claude(Ultra)`, 표에는 저장 당시 요금제인 `Claude(Pro)`로 보이는 불일치를 찾아 고쳤다.
  - 다시 그릴 때(계정 이름 변경 등) 열려 있던 접힘을 유지한다.
- **사용량 필터와 숫자**
  - 필터 줄에는 기간·분류·지표만 둔다. 간격·비교·그래프·범위·초기화와 빠른 선택은 `세부 설정`으로 옮겼다.
    - 세부 설정의 열림 상태는 이 기기에 저장한다.
    - 버튼에는 기본값과 다른 비교·그래프·범위의 수를 표시한다.
    - 필터 요약 줄과 범위 해제 버튼은 그대로다.
  - 모델 표는 줄인 숫자로 시작하고, 정확한 값은 각 칸의 툴팁에 둔다. `숫자 줄여 보기`를 끄면 이 브라우저에서는 정확한 숫자로 보인다.
- KPI 카드의 정의는 바꾸지 않았다. 개요 타일과 같은 합계를 유지하기 위해서다.

    - 한도 이력이 없는 주의 빈 사실
  - Node:

  - 브라우저:
    - 네 탭과 진단 이동·복귀·포커스
    - 머리글 상태 수준과 진단 묶음·개수
    - ⓘ의 툴팁과 접근 가능한 이름
    - 리포트의 사실 문장, 라벨 줄, 접힌 한도 행, 다시 그린 뒤 유지, 현재 계정 이름
    - 세부 설정의 개수와 저장
    - 기본 줄인 숫자와 툴팁의 정확한 값

  - 운영 DB를 읽기 전용 백업으로 임시 경로에 복사하고, GET만 허용한 Chromium으로 열었다.
  - 이 확인에서 찾아 고친 문제:
    - 접히는 패널의 ⓘ가 제목 아래 한 줄을 혼자 차지함
    - 닫힌 패널에서 ⓘ 자리만큼 설명 문구가 어긋남
    - 모바일 세부 설정 버튼의 줄바꿈
    - 품질 표 행 머리의 구분선 누락
    - 한도 표의 계정 이름 불일치
  - 이 확인은 운영 서비스 전환이 아니다.
