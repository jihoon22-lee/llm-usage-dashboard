# 0.14.0 릴리스와 운영 적용

## 범위

0.13.0 배포 뒤 같은 날 이어서 한 작업이다: 추론 수준별 사용량([#114](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/114), [effort-levels](2026-11-10-effort-levels.md)), 보류했던 코드리뷰 항목([#115](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/115), [code-review](2026-11-10-code-review.md)), 버전 준비([#116](https://github.com/jihoon22-lee/llm-usage-dashboard/pull/116)). 세 PR 모두 필수 CI 13개 작업을 통과한 뒤 merge commit으로 병합했다.

## 릴리스

- #116의 merge commit `2efc2e8`에서 main CI가 통과한 뒤 `v0.14.0` 주석 태그를 push했다(사용자 요청).
- 릴리스 workflow의 14개 작업이 통과해 [v0.14.0](https://github.com/jihoon22-lee/llm-usage-dashboard/releases/tag/v0.14.0)이 게시됐다. 내려받은 자산 3개의 SHA-256이 SHA256SUMS와 일치했고 manifest의 태그·버전·커밋이 맞았다. 변경 사항과 업데이트 주의를 노트에 더했다.

## 운영 적용

DB 구조가 바뀌는 배포다(`events`의 `effort`·`speed` 열, `session_effort` 테이블, 롤업 버전 4).

- **백업(19:07 KST):** SQLite 백업 API로 `backups/usage-before-0.14.0.db`(745MB)를 만들고 `quick_check`가 `ok`인 것을 확인했다. 백업 시점의 이벤트는 536,235건, 100,716,949,856토큰이었다.
- **배포(19:08):** 기본 checkout의 main이 `v0.14.0`과 같은 커밋인 것을 확인하고 `packaging/deploy.py`를 실행했다. 릴리스 환경에서 검사를 통과한 뒤 `current`가 `releases/2efc2e8…`로 전환됐다. 두 유닛 `active`, `NRestarts=0`, `/healthz` 정상.
- **전환과 재수집:** 롤업 버전이 4가 됐고, 첫 수집 주기가 원본을 다시 읽어 약 4분 30초 뒤 수집기가 `idle`로 돌아왔다. 이후 이벤트는 536,239건, 100,719,878,624토큰으로, 그 사이 새로 생긴 4건만 늘었다.
- **추론 수준이 채워진 요청 비율:** Codex 99.2%, Devin 99.3%, Claude Code 81.8%, Antigravity 5.9%(모델 이름에 수준이 있는 기록만), OpenCode 0%(원본에 없음). Claude Code의 나머지는 필드가 없던 10월 중순 이전 기록이다.
- **수집 상태:** 배포 뒤 새로 생긴 수집 오류는 없다. `claude-oauth:…`·`claude-resets`의 429는 배포 시작 전(19:05)에 기록된 것이고 재시도 시각이 잡혀 있다.
- **화면:** 실제 운영 화면을 읽기 전용으로 열어(GET만, 차단된 요청 0건) 추론 수준별 사용 패널에 값이 나오고 개요 차트가 패널 높이를 채우는 것을 확인했다. 최근 7일 `claude-opus-5-5`는 요청당 출력이 high 829 → max 1,230 토큰, 출력 중 추론이 36% → 63%다. 캡처는 삭제했다.

## 남은 일

- `backups/usage-before-0.14.0.db`는 다음 일일 자동 백업(11월 11일)이 만들어지면 지운다.
- 속도 등급(`speed`)은 저장만 한다. fast 모드 사용이 생기면 단가에 반영해야 한다.
- 계속 보류: 개요 조회 중 일시 중복 집계, Devin 응답에서 빠진 창, 시계가 앞선 상태줄 이벤트, Antigravity 상태줄의 초기화 시각 형식.
