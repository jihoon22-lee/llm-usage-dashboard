## 운영 적용

DB 구조와 저장 데이터가 바뀌지 않는 배포라 배포 직전 DB 백업은 만들지 않았다.

- **배포(14:04 KST):** 기본 checkout의 main이 `v0.13.0`과 같은 커밋인 것을 확인하고 `.venv/bin/python packaging/deploy.py`를 실행했다. 배포기가 릴리스 환경(uv 0.12.23, Python 3.14.4)을 만들고 그 환경으로 단위 테스트 618개·Node 테스트 45개·문법 검사를 통과한 뒤 `current`를 `releases/c0fe39f…`로 전환했다.
- **확인:** 두 유닛 모두 `active`, `NRestarts=0`, 14:05:00 시작, 작업 디렉터리 `current`. `/healthz`가 `{"ok":true}`를 반환했다.
- **개인 단가 정리:** 내장표가 같은 값을 갖게 된 항목을 지웠다. config 폴더의 `pricing.json`은 빈 객체로, DB 폴더의 `pricing.json`은 공개 단가가 없는 `swe-2`(사용자 가정 $3/$15)만 남겼다. 고치기 전 두 파일은 DB 폴더 `backups/pricing-before-0.13.0/`에 복사해 뒀다.
- **단가 반영 결과(운영 API, GET):** 미산정 모델 0개. 전체 기간 환산 합계 $56,114.76 → $56,028.76(−$86.00), 최근 30일 $21,112.31 → $20,960.65. 작업 기록에서 예상한 차이(−$85.88)와 맞는다. 바뀐 것은 Sonnet 5.5의 캐시 읽기, Sonnet 5의 9월 단가, Opus 5 등의 1시간 캐시 쓰기 단가다.
- **화면:** 실제 운영 화면의 개요·사용량·한도를 1440px·390px·어두운 테마로 읽기 전용 캡처해 확인했다(GET만, 같은 출처만, 차단된 요청 0건). 한 줄 상단 바, 순위의 환산 비용, `비용` 사실, 비용 구성 막대가 보이고 `단가 미등록` 알림이 사라졌다. 캡처와 검토 스크립트는 삭제했다.
