# 클라우드 누락 복구와 한국시간 사용량 통합

## 범위

기존 한도·계정·클라우드 조회를 유지하면서 실제 사용량 반영을 보강한다. 일자는 KST 기준이며
시간 배분을 알 수 없는 합계를 임의로 나누지 않는다. 기본 수집 주기는 5분이다.
시작 main은 `5c58a35`이며 `feat/reconcile-cloud-usage`의 독립 worktree·가상환경에서 작업한다.
uv 0.12.23의 `uv sync --locked`로 개발 의존성을 준비했고 운영 환경은 동기화하지 않았다.

## 구현

- Claude의 teleport 기록에 전체 이벤트와 모델별 결과 누계를 보완한다. 하위 에이전트 전달의
  `parent_tool_use_id`, 중간 출력값, 누계 중복·감소와 페이지 실패를 처리한다.
- 요청 이벤트와 누계 근거를 분리하고, 뒤늦은 상세 기록에 따라 보완량을 다시 계산한다.
- Codex 계정 합계와 선택 기간의 관계를 계산한다. 스레드별 상세는 설치된 App Server의 선택 기능으로
  조회하며 null 응답 때문에 기존 계정 조회가 실패하지 않는다.
- 기간·모델·세션·프로젝트·리포트, KST 구간, 미배분 CSV·화면을 연결한다.
- 별도 키를 쓰는 loopback OTLP/HTTP JSON 수신기를 제공한다. 숫자·식별 정보만 보관하고,
  연결되지 않은 요청은 중복 합산하지 않는다. 실제 CLI·클라우드 설정을 자동 변경하지 않는다.

## 검증

- 운영 DB의 읽기 전용 사본에서 실제 Claude 클라우드 원본을 대조했다. 기준 세션의 요청 기록과
  누계 보완량 합계가 서버의 최종 모델별 누계와 일치했다.
- 과거 다른 세션에는 누계 감소·상세 초과가 있어 충돌로 보존했다. 원격 페이지 수집 완료와 모든 토큰의 의미가 확정됐다는 판단을 구분한다.
- 전체 Python 테스트 358개, JS 테스트 30개와 모든 웹 JS 구문 검사가 통과했다.
- 합성 브라우저 회귀 18종이 통과했다. 새 누계 검사는 1440/390/320px에서 합계·모델·차트·미배분량의
  일치와 KST 표시·가로 넘침을 확인한다. 모바일 화면도 시각 확인했다.
- 원본 대조: Codex 정상 누계 1,239세션, 초기화 58세션, 부분 시작 12세션의 불일치가 0이었다.
  모호한 시각 59세션은 별도 분류됐다. Antigravity 4,213요청과 Devin 42,126요청도 불일치가 0이었다.
- Claude 클라우드 5세션을 실제 응답으로 대조했다. 대형 이력은 20페이지씩 6회에 걸쳐 재개해 모두
  수집됐고 hourly rollup이 요청 이벤트 합계와 일치했다. 기준 세션의 최종 합계는 40,974,996토큰이며
  추론 115,137토큰은 출력에 포함된 별도 값으로 보존됐다.
- Codex 계정 68개 일별 구간을 실제 수신했다. 스레드 상세 조회는 null로 미제공이었고 계정 조회는 유지됐다.
- wheel·sdist 포함 파일·독립 설치·웹 자산·manifest/SHA256 검사를 통과했다. uv build가 만든 dist의
  `.gitignore` 때문에 최초 manifest 검사가 실패해 해당 임시 파일만 제거한 뒤 검증했다.
- 새 Git checkout 설치, 개인정보 패턴·문서 링크 검사도 통과했다.
- telemetry는 인증·형식·잘못된 입력·요청 별칭 연결·중복·본문 비저장을 합성 HTTP/단위 검사로 검증했다.
  실제 CLI에서 송신하도록 설정을 변경하지 않았으므로 실수신 완료로 주장하지 않는다.

## 제약과 운영 상태

내부 API의 외부 연동 허용은 공식 지원으로 확인되지 않았다. 기존 기능은 유지하며 정책 불확실성과
제공사 응답 형식에 대한 의존성을 문서화한다. telemetry 수신기 검사와 실제 CLI 연결은 별개이며,
클라우드 직접 전송은 기본 구성에 연결되지 않았다. 기존 5분 수집은 유지된다.
과거 로컬 기록의 계정 귀속·모호한 초기화는 임의로 복원하지 않는다. 보완 토큰의 비용은 세부 기록과
같은 정도로 확정할 수 없으므로 기존 요청 기반 비용과 구분한다.

초기 구현 검증 시점에는 운영 서비스 정지·환경 변경·배포·릴리스 게시를 수행하지 않았다.
후속 운영 적용 결과는 아래 절에 기록한다.

## 출시 전 리뷰 지적 재현·보강

PR #35의 리뷰 세 건을 대조했다. v0.5.0에서 이 조건이 실제 발생했다는 증거는 없으며 아래는 재현 검증이다.

- 100페이지 초과 transcript를 20페이지씩 이어받아 101페이지 전체 수집 및 완료 후 재조회 생략을 검증했다.
- 계정/미확인 epoch를 저장 키에 추가했다. 이전 계정과 legacy 합계는 보존하고 빈·부분 응답에서 현재
  계정 합계로 노출하지 않는다. 이전 스키마에서 반복 초기화하는 마이그레이션을 확인했다.
- 한도 오류 전후 두 순서로 토큰 응답을 보내 보존됨을 확인했다. 한도 파싱 실패와 계정 변경이 겹쳐도
  토큰 통계가 새 계정 범위로 독립 저장된다. 미확인 계정의 이메일은 해시만 사용하며 DB에 남지 않는다.
- 설치된 Codex의 JSON Schema에서 `account/read`의 refreshToken과 workspaceRouting을 확인했다.
- 보강 후 Python 전체 364개 테스트 통과. 브라우저 smoke·KST 보완량 검사와 실제 원본 합계 대조를
  다시 실행해 통과했다(기존 Codex·Antigravity·Devin 불일치 0). 계정 테이블은 원래 테이블을 유지하는
  추가 마이그레이션으로 이전 릴리스의 스키마 호환성도 보존한다. 필수 CI 완료 전 병합하지 않는다.

## main 병합과 v0.6.0 준비

- 사용자 지시로 원격 push·PR·릴리스·운영 배포까지 범위를 확대했다.
- PR #38의 보강 commit `a4ff844`에서 Python 4개 조합·JS·브라우저 18종·패키지·보안·CodeQL과
  최종 `ci-required`가 모두 성공한 뒤 merge commit으로 main에 병합했다.
- 실제 Codex에서도 계정 일별 합계 68개와 account/read 응답을 받았고 한도 응답의 계정 ID와 일치했다.
  이메일과 식별 원문은 작업 기록이나 출력에 남기지 않았다.
- v0.6.0의 프로젝트 버전·lock·CHANGELOG·설치 및 운영 안내를 갱신한다. 외부 의존성은 유지한다.
- 운영 배포는 아직 미실행이다. 무암호 sudo는 restart만 허용하므로 서비스 정지는 사용자 터미널의
  관리자 인증이 필요하다. 릴리스 완료 후 두 서비스 정지를 확인하고 환경·릴리스를 전환한다.

## v0.6.0 릴리스·운영 검증

- 구현 PR #38 merge `9bc18a4`, 버전 PR #39 merge `b796103`. 각각 필수 CI 성공 후 병합했다.
- `b796103` main CI 성공을 확인한 뒤 v0.6.0 태그를 push했다. Release 워크플로도 성공했고
  immutable 릴리스의 wheel·sdist·manifest를 다운로드해 SHA256SUMS와 모두 일치함을 확인했다.
- 사용자 터미널에서 두 서비스를 정지했다. inactive·MainPID 0을 확인한 뒤 기본 main을 태그로
  fast-forward하고 uv 0.12.23으로 운영 `.venv`에 `uv sync --locked --no-dev`를 적용했다.
  프로젝트만 0.5.0→0.6.0으로 바뀌었고 외부 패키지는 유지됐다.
- 배포기의 JS 30개·전체 JS 구문·Python 364개 검사 후 전환·재시작에 성공했다. 두 PID의 실제 cwd가
  `releases/b796103…`였고 health 200·새 heartbeat를 확인했다. 사설 주소의 실제 인증된
  PC·390px 모바일 read-only 브라우저 smoke도 통과했다.
- 실제 인증·CSRF를 거친 수동 갱신 요청 109–112가 완료됐다. 기존 진행분을 이어받아 Claude 5세션
  전체 페이지 수집이 완료됐고 남은 cursor는 0, 소스는 ok다. 누계 의미 충돌 1건은 별도 표시한다.
- 한국시간 오늘의 클라우드 요청 기록 40,507,027 + 누계 보완 467,969 = 40,974,996토큰 반영을 확인했다.
  Codex는 현재 계정 범위로 68개 일별 합계를 저장했다. 스레드별 상세는 여전히 미제공이고,
  telemetry 실수신은 설정하지 않아 unavailable이다.
- 복구 기준은 이전 릴리스 `667d5c4`와 기존 10-12 11:11 KST DB 백업이다. 백업을 삭제·교체하지 않았다.

## 사용량 대조 표시 간소화 · v0.6.1

사용자가 운영 화면의 긴 대조 문구를 지적해 후속 UI 수정을 추가했다. 기본 요약에는 보완량·날짜 미배분
구간 수·충돌 건수만 남기고, 출처·구간 목록·집계 기준은 상세 보기에 유지한다. PC는 한 줄, 320px
모바일은 두 줄이며 날짜 목록은 열었을 때만 표시한다. 자동 갱신 후 열림 상태와 키보드 포커스를 유지한다.

JS 전체 구문·30개 단위 검사와 browser smoke를 확인했다. 1440/390/320px에서 실제 브라우저로
접기·키보드·갱신 상태·합계 동일성과 가로 넘침을 검사하고, 운영 수치를 넣은 미리보기도 시각 확인했다.
집계·수집 로직과 외부 의존성을 바꾸지 않고 프로젝트 버전만 0.6.1로 갱신한다.

### 일시 조회 실패에서 기존 관측 유지

추가 점검에서 Codex 조회 전체가 실패하면 계정 관측을 미확인으로 바꾸어 이전 합계가 화면에서 빠지는
회귀를 재현했다. 새 응답이 없으면 기존 계정과 수신 시각을 유지하고 수집 실패를 별도로 표시한다.
반대로 새 토큰 통계가 왔지만 계정 메타데이터가 없거나 잘못된 형식이면 미확인 epoch에 분리한다.
재현 테스트의 수정 전 실패를 확인한 뒤 두 경계를 회귀 검사에 추가했다. Python 366개 전체 검사와
브라우저 smoke가 통과했다.
