# 전체 코드 검토 후속 수정

## 범위와 실행 규칙

검토에서 확정한 10개 문제를 수정하고 회귀 검사, PR/필수 CI, 운영 배포와 정리까지 수행한다.
기준 main은 `b2a3a17`, 작업 시작 당시 운영 코드는 `7f89e6b`이다.
개발 checkout과 공유 운영 `.venv`, 기존 `releases/<commit>` 및 `current` 구조를 유지한다.
독립 worktree와 uv 0.12.23 환경에서 검증하며 의존성·DB 스키마·운영 설정은 변경하지 않는다.
별도 백업/배포 후보 디렉터리를 만들지 않으며 과거 DB 일괄 변환과 릴리스 태그 변경은 범위 밖이다.

## 실행 계획과 진행

1. 비교 차트: 현재/비교 라벨과 기타 그룹을 맞추고 이전 기간 전용 라벨 및 숨김을 처리한다.
2. 프로젝트 세션: 기간·필터 전체에서 DISTINCT session을 계산한다.
3. Codex 체크포인트: 신규 이벤트만 경로를 정규화하고 기존 이벤트의 프로젝트명은 보존한다.
4. 단가: 정확한 모델명과 괄호 제거 후 정확 일치를 접두어보다 우선한다.
5. 점유율 꺾은선: 누적 좌표 대신 개별 비중을 그린다.
6. 설정: 최신 파일 읽기·부분 병합·원자 저장·메모리 반영을 직렬화하고 실패 시 기존 값을 보존한다.
7. Antigravity 검증: alias 연결과 스트리밍 최종 관측을 독립적으로 대조한다.
8. 배포 DB: 실제 서비스 설정의 database를 확인하고 heartbeat에 사용한다.
9. 배포 신호: 비정상/0 PID에 신호를 보내지 않는다.
10. 운영 문서: 없는 배포 직전 DB 백업 보장을 제거한다.

각 단계는 실패하는 회귀 검사 → 최소 수정 → 관련 검증 → 커밋 순서다.
최종적으로 전체 Python/JavaScript/브라우저 검사, 영역별 독립 교차 검토, PR의 ci-required 성공을 요구한다.
운영 배포는 기존 의존성을 확인한 뒤 코드만 전환하고 실행 경로·health·heartbeat·인증된 화면·원본 대조를 확인한다.
작업 브랜치/worktree, 임시 환경과 프로세스는 마지막에 정리한다.

## 설계 판단

- Codex 재구성은 기존 행을 삭제 후 재생성한다. 체크포인트만 정규화하면 과거 이름도 바뀌므로 이벤트 ID별 기존 프로젝트 속성을 먼저 보존한다.
- 설정은 쓰기만 잠그면 오래된 부분 객체가 최신 필드를 덮어쓴다. 요청 필드 병합까지 잠금 안에서 처리한다.
- 문서/진행 기록은 이 파일 하나로 관리한다. 스킬용 중복 계획/장부 대신 이 기록과 Git 커밋을 진행 근거로 사용한다.
- 단가 수정으로 동적 비용 추정은 달라질 수 있다. 기존 주간 보고서는 생성 당시의 저장된 결과이며 자동 재작성하지 않는다.

## 검증과 운영 결과

- 비교 차트: 기대 210 / 실제 140으로 실패를 확인한 뒤 공유 라벨/기타 매핑을 적용했다. 이전 기간 전용 라벨, 빈 현재 기간, 범례 숨김, 토큰/요청/비용과 모바일 재현이 통과했다.
- 프로젝트 세션: 동일 세션이 3으로 집계되는 실패를 확인한 뒤 기간 전체 DISTINCT로 수정했다. 기간/모델/서비스/프로젝트 필터와 토큰·요청 수 보존 검사를 통과했다.
- 독립 환경 기준 검사: Python 256개 통과. 위 수정 후 test_usage 및 모델 표시/인사이트 브라우저 검사를 실행했다.
- 운영 변경은 아직 수행하지 않았다.

- Codex 체크포인트: Windows/POSIX/UNC/루트의 신규 기록 경로 잔존 실패를 먼저 확인했다. 정규화와 기존 ID별 프로젝트 보존 후 재시작·복사본·추가 수집 검사 및 collection integrity 13개, privacy 15개, usage 46개가 통과했다.

- 단가/점유율: mini(high) 오선택과 미등록 nano(high)의 상위 모델 추정, 점유율 25/75→50/50에서 두 번째 선 100% 고정 실패를 확인했다. 정확한 기본 모델 우선과 개별 비중 좌표로 수정했고 pricing 2개, usage 46개, 실제 브라우저 좌표/툴팁 및 dashboard 검사가 통과했다. 모바일 resize 재그리기와 focus가 경쟁하던 새 테스트는 두 animation frame 완료를 기다려 안정화했다.

- 설정 저장: 스레드/프로세스의 저장 유실, 손상 파일 덮어쓰기와 실패 시 메모리 선반영을 실패 검사로 확인했다. 고정 local.lock의 프로세스 잠금과 스레드 잠금, 최신 값 기반 부분 갱신, 성공 후 메모리 반영을 적용했다. 동시 저장 8개, privacy 15개, usage 46개 및 브라우저 개인정보 검사가 통과했다. 운영 설정에는 쓰지 않았다.

- Antigravity 검증: 정상 streaming/alias 확장에서 3요청·3불일치·2alias 오류로 실패하는 재현을 확인했다. 원본 alias 연결요소와 완료/최대 관측으로 독립 대조하도록 수정했다. 파일 순서, 전이 연결, 실제 토큰 변조·누락·alias 분리/누락·원본 충돌·출력 분할 오류를 포함한 4개 새 검사, 기존 verify 및 history 20개가 통과했다.

- 배포/문서: custom DB, 두 유닛 설정 불일치·환경 덮어쓰기·잘못된 설정, PID 0/음수/빈 값/비숫자의 실패 경로를 검사했다. heartbeat는 검증된 DB를 명시적으로 전달받으며 서비스 설정 확인은 전환 전에 끝난다. 배포 관련 11개 및 공개 문서 검사가 통과했다. 없는 사전 DB 백업 보장을 제거하고 기존 주기 백업·코드 롤백 범위를 문서화했다.

### 5. PR 병합과 운영 배포

- [ ] 원격 main의 새 변경을 확인하고 PR을 만든다. 통합으로 코드가 달라지면 관련 검사를 다시 수행한다.
- [ ] 보호 규칙을 지켜 merge commit으로 병합하고 현재 개발 경로의 main을 fast-forward한다.
- [ ] 병합한 SHA를 기존 `releases/<commit>` 구조에 배포한다. 기존 deploy 명령의 검사를 통과한 뒤 current 전환과 두 서비스 재시작을 수행한다.
- [ ] 재시작 후 실제 실행 SHA/경로, 두 서비스 상태, health, 수집 heartbeat를 확인한다.
- [ ] 실제 인증된 화면에서 비교/누적/점유율, 토큰·요청·비용, 프로젝트 필터, 데스크톱·모바일 동작을 확인한다. 읽기 전용 검증으로 운영 설정이나 제공사 인증을 변경하지 않는다.
- [ ] 배포 후 원본 대조와 수집 오류를 확인한다. 실패하면 기존 배포기의 코드 rollback을 사용하고 복구된 서비스 상태까지 확인한다. DB 일괄 변환이나 복원은 수행하지 않는다.

### 6. 기록과 정리

- [ ] 이 문서에 최종 PR·CI·배포 SHA와 검증 결과를 기록한다. 병합 후 문서 보완도 보호된 PR 절차를 따른다.

- [ ] 운영 .venv·데이터·설정·기존 릴리스는 보존한다. 미병합 작업은 강제로 삭제하지 않는다.
