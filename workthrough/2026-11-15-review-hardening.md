## 고친 것

### 추론 수준
- 모델 이름 끝의 `-max`·`-high` 같은 단어를 어느 경로에서나 추론 수준으로 읽었다. 이름으로 수준을 밝히는 경로(Devin, Antigravity)에서만 읽는다. Codex의 `…-codex-max` 같은 모델은 턴 설정의 수준을 따르고, 추론 수준별 표에서 이름이 잘리지 않는다. DB 구조를 올릴 때의 채우기도 같은 경로로 한정했다.
- Devin 모델 이름에서 떼는 수준 단어가 저장 쪽 목록과 달랐다(`xhigh`·`minimal` 누락). 같은 목록을 쓴다.
- 추론 수준별 표의 `출력 중 추론`은 추론 값을 받은 요청만의 합을 전체 출력으로 나눈 값이다. 일부 요청만 값을 보낸 행에는 `수신 N건`을 함께 적는다.
- 인사이트 구획만 요청할 때는 쓰지 않는 추론 수준별 집계를 건너뛴다.

### 개요
- Claude 계정이 여러 개일 때 쉬는 원래 계정이 서비스 전체 사용량을 물려받아 `기록 없는 구독`으로 잡히지 않았다. 사용량 탭처럼 계정별 사용량만 본다.

### 수집기
- 대기 중인 2초 루프가 매번 heartbeat를 DB에 기록했다(하루 약 4만 3천 번). 수집을 마칠 때와 대기 중 30초마다 기록한다. 화면의 수집기 정지 판정(`stale_seconds`, 최소 60초), 재시작 알림(10분), 배포기의 heartbeat 확인(180초)은 그대로 동작한다.
- 알림 판단·주간 리포트·월 정산이 한 묶음이어서 하나가 실패하면 나머지도 그 회차에 건너뛰었고, 실패는 모두 `알림 판단 실패`로 적혔다. 셋을 따로 실행하고 실패한 단계의 이름을 적는다.
- `local.json`을 읽지 못하면 표시 없이 기본 설정으로 돌아가 웹에서 바꾼 알림·구독료·종료 구독이 적용되지 않았다. 수집 상태에 `웹 설정` 오류로 적고, 다시 읽히면 지운다. 객체가 아닌 JSON(숫자 등)이면 수집기가 예외로 멈추던 것도 기본 설정으로 읽는다.
- Codex 작업 목록의 `invalid` 카운터가 매 수집마다 같은 항목을 다시 더했다. 그 회차에 건너뛴 수만 적는다.

### 알림
- 알림 전송만 리다이렉트를 따라갔다. 다른 외부 호출처럼 따라가지 않으며, 리다이렉트 응답은 전송 실패(`HTTP 3xx`)로 남는다.

### 상태 표시와 로그
- 백업·원본 대조 실패의 예외 문장이 그대로 상태 API에 실렸다(경로가 섞일 수 있다). 예외 종류와, 파일 오류면 시스템이 준 사유만 적는다.
- 사용량·Codex 작업·수동 자원 API가 값 오류를 모두 400으로 바꿔, 서버 쪽 결함이 입력 오류처럼 보이고 흔적이 남지 않았다. 응답은 그대로 두고, 예외 종류와 발생 위치(파일:줄)를 한 줄로 로그에 남긴다. 예외 문장과 요청 값은 남기지 않는다.

### 배포기
- 배포 확인에 실패해 이전 릴리스로 복귀할 때 복귀 재시작의 결과를 보지 않고 `되돌렸습니다`로 끝났다. 복귀 재시작도 확인되지 않으면 그렇게 알린다.

## 남은 제약

- 다른 설치의 DB에 Codex·OpenCode 모델 이름 끝 단어가 추론 수준으로 이미 저장돼 있다면 그대로 남는다. 턴 설정에서 온 값과 구분할 수 없어 고치지 않았다. 이 PC의 DB에는 그런 행이 없다.
- `출력 중 추론`은 여전히 하한이다. 시간별 집계에는 추론 값을 보낸 요청만의 출력 합이 없다.
- 알림 채널이 리다이렉트로만 응답하면 이제 전송 실패로 보인다. 최종 주소를 직접 설정해야 한다.
